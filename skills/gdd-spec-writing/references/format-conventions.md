# 規格書格式慣例

新規格必須讀起來像是同一個人寫的。這份文件講的是**怎麼歸納出一個 vault 的慣例**，以及 `GDD_DungeonZoo` 這個 vault 目前的慣例是什麼。如果你在別的專案用這個 skill，先跑一次「怎麼歸納」那節，再把下面的「現行慣例」換掉。

---

## 一、怎麼歸納一個 vault 的格式慣例

打開三到五份**已完成**的規格（不要拿半成品當範本），觀察這幾個維度：

1. **H2 標題的型態** — 是 `## 【名稱】`、`## ① 名稱 ----`、還是 `## 1. 名稱`？同一個 vault 常有兩三種模板並存，各自對應不同性質的文件，要找出分工規律。
2. **首行有沒有固定元素** — 很多 vault 習慣第一行就是內嵌示意圖。
3. **條列的粗體慣例** — 是 `- **關鍵詞**：說明`，還是整句粗體？中英夾雜的寫法為何？
4. **表格用在什麼場合** — 通常是分類對照、狀態對照、結算規則這三種。表頭欄位名加不加粗？格內怎麼換行？
5. **數值佔位的寫法** — `{數值}`、`{1~5}`、`[變數名]`、反引號包固定字串。
6. **公式怎麼寫** — 純文字、行內 LaTeX、還是區塊 LaTeX？
7. **wikilink 的句式** — 指向其他規格時固定用什麼句子收尾？連結用檔名還是別名？

歸納完，挑兩三份實際檔案當「代表範例」記下來，寫新規格時對照著看。

## 二、GDD_DungeonZoo 現行慣例

### 三種模板並存，依文件性質分工

**1. 【】章節式** — 純機制／系統規格最常用

- H2 一律 `## 【功能區塊名】`，全形方括號，動詞化命名：`【核心捕獲機制】`、`【死亡懲罰機制】`
- H3 為次分節，純文字＋（英文術語）：`### 狀態機（State Machine）切換`
- 代表：`玩家角色.md`、`展示魔物.md`、`魔物行為與戰鬥.md`、`營業時間與流速控制按鈕.md`

**2. 圈號拆解式** — 畫面／介面總覽用

- H2 為 `## ① 區塊名 ------------------------------------`，圈號 ①～⑮ ＋ 尾端補一串半形破折線對齊
- 每個圈號一段導言 ＋ 固定收尾句「詳細請參考[[X]]規格」
- 代表：`基本設計(動物園經營).md`（①～⑮）、`地下城進入預覽頁面.md`（①～⑧）

**3. 編號系統式** — 有流程或公式的系統文件

- `## 1. 名稱` → `## 2. 名稱`，H3 用 `### 1.1` 或回頭混用 `### 【小節名】`
- 代表：`待分發魔物列表UI.md`、`動物園破產.md`、`動物園結算.md`

> 註：`待分發魔物列表UI` 與 `動物園破產` 開頭有 `## 1. 系統概述`（含「功能定位／核心操作」兩條），但企畫已表示**新規格不要這個區塊**。改為在第一個 H2 底下直接放一到兩段導言，寫法比照 `展示區管理頁面.md` 的開場。

### 共同細則

- **首行必為內嵌圖**：`![[zoo_employee.png]]`，可帶寬度 `![[zoo_employee.png|471]]`。分節配圖插在對應 H2 之前，形成「圖 → 標題 → 內文」的節奏。
  - 路徑不統一：多數為裸檔名，少數帶資料夾 `![[image/zoo_enclosure_ui.png]]`。兩種都能運作，跟著鄰近檔案走即可。
  - **還沒有示意圖時**，第一行改放 `> ※ 介面示意圖待補（暫定檔名：\`xxx.png\`）`，不要放一個會壞掉的內嵌連結。
- **條列格式**：`- **粗體關鍵詞（English Term）**：說明文`。巢狀最多 2~3 層。重點用 `**…**` 包住整句而非單詞。
- **表格**：專用於分類對照／狀態對照／結算規則。表頭欄位名加粗（`| **層級** | **名稱** |`），格內以 `<br>` 換行、`・` 或 `•` 當次項目符號。
- **數值佔位**：`{數值}`、`{1~5}`、`[當前層數] / [該地城總層數]`。固定字串用反引號：`` `001` ``、`` `+X` ``。
- **公式**：行內 `$\le$`、`$X$`；區塊 `$$\text{緊急販賣價格} = \text{基礎價值} \times 0.4$$`。
- **金額**：一律 `${數值}`，並註明「強制支援千分位逗號」。日薪類寫成 `${數值}/每日`。
- **wikilink 句式**：固定兩種收尾——「（詳細請參考[[X]]規格）」與「（請參考[[X]]規格頁面）」。連結一律指檔名，不使用別名。
  - **檔名不要有斜線**。`[[聘雇員工/員工管理頁面]]` 這種寫法會被 Obsidian 當成資料夾路徑，是死連結。

### 常見的規格區塊

寫介面類規格時，這幾個區塊幾乎必備（順序可調）：

- 介面定位與開啟方式（觸發時機、介面型態、關閉行為）
- 資料欄位規格表（欄位名／支援排序／顯示格式）
- 互動與 UI 層級邏輯（點擊行為、鏡頭行為、Z-Order）
- 防呆規則（壓灰上鎖條件、Tooltip 文案、空狀態表現）
- 跨階段權限（準備階段 vs 營業階段的差異表）
- 關聯規格（wikilink 清單）

### 專案專屬的既有決策（寫新規格時務必沿用）

- **階段劃分**：準備階段（時間靜止，可編輯）／營業階段（時間流動，多數編輯功能唯讀上鎖）
- **排序機制**：`▲`／`▼` 高亮與壓灰規則，母規格在 `展示區管理頁面.md`，其他表格頁一律引用而非重寫
- **二次確認彈窗**：破壞性操作（解僱、販賣、拆除）都要，文案格式為斜體單句
- **小紅點（Badge）**：僅用於「有待處理事項」的主畫面功能按鈕，內含數字。頁籤類不使用。
- **員工屬性用語**：等級 `Lv.{1~5}`、反應速度五階（非常快／快／普通／慢／非常慢）、積極度 `0~100` Slider
- **種族清單**：人類／月族／獸人族／高等魔物／妖精（定義在 `遊客.md`）

### 已知的全域矛盾（尚未裁決，寫作時避免選邊站，或先問企畫）

- **貨幣三個名字**：`營運幣`（動物園）／`金幣`（README、升級條件）／`古代錢幣 G`（地下城戰利品）。三者關係未定義。
- **名聲可不可以減**：`動物園等級與升級按鈕` 說是不消耗的歷史累加值，`營運幣與名聲`／`動物園結算` 說可增可減。
- **魔物分類與屬性**：`展示魔物` 定義分類＝不定型／動物／半獸／矮人系，屬性八種；`待分發魔物列表UI` 卻寫野獸系／不死系、屬性有「草」。
- **管理頁面營業時是否上鎖**：`基本設計(動物園經營)`⑥ 與 `營業時間與流速控制按鈕` 說上鎖，`展示區管理頁面` 說全階段無區別。
- **級別對應**：`級別.md` 朽木級＝Lv1，`大地圖場景.md` 範例寫「朽木級(Lv2)」。

## 三、Git commit 慣例

`GDD_DungeonZoo` 的既有 commit message 格式：

```
撰寫"展示區管理頁面"規格及新增示意圖
撰寫"動物園結算"規格&新增示意圖
1.撰寫"待分發魔物列表UI"規格&新增示意圖 2.規格改名(待分發魔物頁面 -> 待分發魔物列表UI)
重新整理動物園相關規格中的編號導連
```

規律：`撰寫"檔名"規格`，有附圖才加 `&新增示意圖`，一次做多件事就用 `1. … 2. …` 編號。沿用即可，不要換成 Conventional Commits 之類的風格。
