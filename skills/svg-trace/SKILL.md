# svg-trace

一次一張圖, 由 AI **用 SVG 基本圖形組出來**, 再轉成 PowerPoint 原生圖案。使用者拿到 pptx 之後是「當素材改」——進 PowerPoint 換文字、換配色、搬框線, 併進自己的簡報。

**唯一的硬性要求是「進 PowerPoint 改得動」, 相似度不是。** 兩者衝突時一律犧牲相似度。具體來說:

- 不追求像素級相似, 也不要為了更像而增加圖案數
- 陰影、材質、雜點、手繪抖動一律不畫
- 不做逐像素描邊 (那會產出上千個碎片, 在 PowerPoint 裡選都選不動)
- 寧可少畫一個細節, 也不要多出一個使用者不知道怎麼選的形狀

設計理由詳見 `docs/2026-09-17-svg-trace-design.md`, 需要時才讀。

畫 SVG 前一定先讀 `references/svg-rules.md` (viewBox 換算、支援語法子集、分群慣例), 不要憑印象畫。

不做批次, 一次只處理一張圖: 自我校正迴圈需要專注比對, 多張同跑會讓錯誤互相掩蓋。

以下指令一律用 `py -3`, 不寫死版本號。

## 取得圖檔

三種方式, 依這個優先序判斷使用者給的是哪一種:

1. **剪貼簿 (推薦)** — 使用者截圖 (`Win+Shift+S`) 後直接說「描圖」, 沒給任何路徑。跑:

   ```
   py -3 ~/.claude/skills/svg-trace/scripts/svgtrace.py grab
   ```

   省略 `--out` 時會自動開一個帶時間戳的工作資料夾, 存成 `source.png`。剪貼簿沒有影像時腳本會明確回報「剪貼簿沒有圖片」, 這時候問使用者要不要改給路徑。

2. **檔案路徑** — 使用者拖檔進終端機或直接打路徑, 照給的路徑用即可, 不必跑 `grab`。

3. **貼進對話 (Ctrl+V)** — AI 看得到圖但磁碟上沒有檔案。**這時仍要順手跑一次 `grab`**: 使用者既然貼得出來, 圖多半還在剪貼簿裡。撈到了就當成方式 1, 升級成完整流程 (有 `palette` 取色、有並排比對); 撈不到才退化成**目視模式**——只看對話裡貼的圖目測畫 SVG, 沒有真實取色也沒有並排比對, 校正迴圈全靠 AI 自己看貼進來的圖跟 `render` 出來的截圖比。

## 分流

拿到圖先看過, 講一句適合度評估再動手:

**任何圖都畫, 不退件。** 分流只決定「要簡化到什麼程度」與「先講什麼預期」, 不決定做不做。

| 圖種 | 簡化程度 | 開場要講的一句話 |
| --- | --- | --- |
| 向量感的圖 (流程圖、架構圖、示意圖、時序圖、心智圖) | 幾乎不用簡化 | 主場, 直接做 |
| UI 截圖 | 中 | 陰影與細部材質會拿掉, 文字會是真的文字框 |
| 資料圖表 | 中 | 會讀出數據重畫, 不照著描, 這樣數字之後才改得動 |
| 卡通、插畫、logo | 高 | 會變成色塊與線條組成的簡化版, 不會像原圖那麼細 |
| 照片、寫實圖 | 極高 | 只會抓出幾個大色塊與輪廓, 結果比較像海報化的示意圖而不是那張照片 |

講完就動手, 不要問「還要做嗎」, 也不要勸第二次。

## 七步流程

1. **取得圖檔** — 見上一節, 確保磁碟上有檔案 (或確認進入目視退化模式)
2. **分流** — 一句話講適合度評估 (見上表)
3. **取色** — 有圖檔就跑, 拿真實 hex 不要憑印象猜色:

   ```
   py -3 ~/.claude/skills/svg-trace/scripts/svgtrace.py palette <圖片路徑>
   ```

   量化出的主色只回答「這張圖大致有哪些色」; 某條線某個色塊要問到精確色時加 `--at x,y` (可重複給多個座標):

   ```
   py -3 ~/.claude/skills/svg-trace/scripts/svgtrace.py palette <圖片路徑> --at 120,80 --at 400,220
   ```

4. **畫 SVG** — 依 `references/svg-rules.md` 落檔。檔名主幹跟來源圖對齊 (例如來源是 `foo.png` 就存成 `foo.svg`), 因為之後 `render --against` 產出的並排比對圖檔名是從 SVG 路徑推導的, 不是從原圖路徑推導的, 檔名主幹沒對齊會讓後續產物對不起來
5. **自我校正迴圈, 上限 5 輪** — 見下一節
6. **交件比對** — 跑並排比對圖給使用者看, 等他點名要改的地方, 改到滿意為止:

   ```
   py -3 ~/.claude/skills/svg-trace/scripts/svgtrace.py render <svg路徑> --against <原圖路徑>
   ```

   會先截圖再產出並排比對圖 (原圖在左標 `ORIGINAL`, 臨摹在右標 `TRACE`), 存在 `<svg檔名>.compare.png`。目視退化模式沒有原圖檔案, 跳過 `--against`, 改成 AI 自己拿貼進對話的圖跟純截圖比對。

7. **出檔** — 產 pptx:

   ```
   py -3 ~/.claude/skills/svg-trace/scripts/svgtrace.py build <svg路徑> --out <pptx路徑>
   ```

   跑完會印出**這頁的圖案數與 60 個的預算**。超出就是畫太細了, 依 `references/svg-rules.md` 的「圖案數預算」合併或砍掉細節再重畫 — 這是硬性要求, 不是建議, 因為形狀一多使用者在 PowerPoint 裡就選不到想要的那個, 整份東西失去意義。

   `--out` 指到的檔不存在時新建 16:9 空白檔; 已存在時直接**追加一頁**, 沿用該檔原本的投影片尺寸, 所以可以直接往使用者自己的簡報裡加而不會破壞版面。SVG 裡有轉換器不支援的元素時非零退出、不產半成品, 但一次**最多只列出 8 個**, 超過會註明還有幾個沒列出; 修完這 8 個很可能還沒完, 要再跑一次才知道有沒有清乾淨。

## 自我校正迴圈 (步驟 5, 上限 5 輪)

每一輪:

1. 跑 `render` 截圖。**有原圖檔案時**帶 `--against` 產並排比對圖:

   ```
   py -3 ~/.claude/skills/svg-trace/scripts/svgtrace.py render <svg路徑> --against <原圖路徑>
   ```

   **目視退化模式沒有原圖檔案**, 這裡不能帶 `--against` (會找不到檔案報錯), 改成不帶 `--against` 單純截圖:

   ```
   py -3 ~/.claude/skills/svg-trace/scripts/svgtrace.py render <svg路徑>
   ```

   截完自己拿貼進對話的原圖跟這張截圖比對, 沒有並排合成圖可看。

2. AI 自己看比對結果 (並排圖或前一步兩張圖對照), 挑出差最多的幾處
3. 修 SVG
4. 回報一句「這輪修了什麼」, 讓使用者看得出是在收斂還是原地打轉

跑滿 5 輪就停, 進入步驟 6 交給使用者確認; 提早收斂 (看不出還有值得修的差異) 就提早結束, 不必硬跑滿 5 輪。

**卡通角色、人物這類有機造型通常要用滿**: 這種圖的失敗模式是「結構抓錯」而不是「位置差幾格」, 前一兩輪往往在修比例, 第三輪才會發現真正的結構問題 (例如張開的嘴其實是上顎與下顎兩塊夾出來的, 不是一塊頭加一片暗色), 改完結構還需要輪次收尾。流程圖、架構圖這種幾何圖形則常常兩輪就收斂, 不必硬跑。

## 產物位置

**有給圖片路徑時**, 產物放原圖旁邊:

```
<原檔名>.svg
<原檔名>.compare.png
<原檔名>.pptx
```

**走剪貼簿時**, 產物都在 `grab` 開的工作資料夾裡 (`~/svg-trace/<時間戳>/`):

```
source.png
trace.svg
trace.compare.png
trace.pptx
```

`.svg` 一定保留, 不要事後刪掉——使用者之後要改時, 改 SVG 重 `build` 比在 PowerPoint 裡救快。

另外校正迴圈期間, `render` 不帶 `--out` 時會在 SVG 旁邊留下 `<svg檔名>.render.png`——這是每輪截圖用的中間產物, 每跑一次就覆寫一次, 不是最終交付的一部分, 使用者若在資料夾裡看到它不用理會。

## 相依

```
py -3 -m pip install python-pptx
```

`python-pptx` 會一併帶進 `lxml` 與 `Pillow`。另外需要 Chrome 或 Edge (`render` 用來截圖), 兩者裝一個就夠, 不用額外裝 cairosvg、Inkscape、ImageMagick 或 LibreOffice。

## 常見失敗

- **`build` 說檔案正在被開著**: 目標 pptx 正在 PowerPoint 裡打開, 請使用者先關掉再重跑
- **`render` 找不到 Chrome 或 Edge**: 錯誤訊息會列出找過的路徑。可設環境變數 `CHROME` 指到瀏覽器執行檔的完整路徑再重跑
- **`grab` 說剪貼簿沒有圖片**: 提醒使用者先 `Win+Shift+S` 截圖, 或改給檔案路徑
- **`build` 說 SVG 含不支援元素**: 一次最多列出 8 個, 超過會註明還有幾個沒列出。對照 `references/svg-rules.md` 的「不支援」一節修掉重跑; 若訊息有註明「還有 N 個」, 修完這 8 個後還要再跑一次確認清乾淨, 不要看到清單變短就以為結束了
- **`render` 逾時**: 瀏覽器截圖超過 60 秒、剪貼簿操作超過 30 秒沒回應會回報逾時, 通常是瀏覽器程序卡住, 重跑一次即可
