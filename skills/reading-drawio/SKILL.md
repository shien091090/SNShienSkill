# 讀 draw.io 檔案

**核心原則：畫面看起來正確 ≠ 資料是正確的。** draw.io 的視覺呈現與底層 XML 可以不一致——標籤脫鉤、線沒接上、群組沒建立，畫面上完全看不出來。所以**先驗結構，再讀內容**，且回報前要分清「我讀到的」與「我推測的」。

## 快速流程

```bash
# 1. 先看是不是純 XML（壓縮版直接 cat 是亂碼）
head -c 300 "<檔案>"

# 2. 跑解析器（自動處理壓縮、object 包裝、連線標籤、結構檢查）
python <skill目錄>/parse_drawio.py "<檔案>" --out report.txt [--json g.json]

# 3. 讀報告（一定用 cat，不要靠 python stdout）
cat report.txt
```

`--json` 產出機器可讀的 nodes/edges/annotations，要轉 LangGraph、spec 或程式碼時用。

## 🔴 七個雷（每一個都實際踩過）

| # | 雷 | 症狀 | 正解 |
|:-:|:--|:--|:--|
| 1 | **壓縮存檔** | `cat` 出一串 base64 亂碼 | `<diagram>` 內是 base64 + raw deflate + urlencode。解析器已處理。請使用者到「檔案→內容」取消 Compressed，之後 git diff 也能看 |
| 2 | **Windows cp950** | 中文變 `�`，emoji 直接 `UnicodeEncodeError` | **永遠把報告寫成 UTF-8 檔再 `cat`**，不要 `print` 中文到 stdout |
| 3 | **連線標籤不是節點** | 判斷節點的「通過/不通過」全部讀成無標籤，或多出一堆座標 (0,x) 的怪節點 | 標籤是 `parent=<edge id>` 的子 vertex。必須把它從節點清單移除、掛回該條 edge |
| 4 | **脫鉤標籤** | 某標籤 `style` 含 `edgeLabel` 但 `parent="1"` | 它**本來是連線標籤**，只是掉到畫布上了。畫面看起來正常，程式讀起來是「線沒標籤 + 一個孤島」。**不要說它「被畫成獨立方塊」** |
| 5 | **註解歸屬用錯距離** | 把 `[用途]` 歸到旁邊的判斷菱形 | 用**幾何中心 + 歐氏距離**。左上角 + 曼哈頓距離會讓菱形贏，曾因此誤報 4 個錯誤給使用者 |
| 6 | **註解算進連通性** | 報出幾十個假孤島、圖「斷成 28 塊」 | `[輸入]`/`[驗收條件]`/`[用途]` 本來就不連線。連通性只算流程節點 |
| 7 | **同名節點** | 報告裡三個「人類檢查」分不清誰是誰 | 一律在名稱後加 id 尾碼（`人類檢查#40`）。同時提醒使用者：轉程式會撞名 |

## 結構檢查清單

解析器都會跑，回報時逐項確認：

- **懸空連線** — `source`/`target` 為空
- **脫鉤標籤** — 雷 4
- **孤島節點** — 流程節點 in=0 且 out=0
- **弱連通分量** — >1 塊代表圖是斷的，通常是漏畫線
- **判斷節點出口** — 應 ≥2 且每條都有標籤。出口=1 等於不是判斷；出口=0 是缺結束節點
- **標籤語意對稱** — 「是否有 X」的出口該是 `有`/`沒有`，不該混 `有`/`通過`
- **同名節點** — 雷 7
- **殘留 HTML** — 值裡有 `<div><br/>`，多按換行造成，機器讀會帶雜訊

## 回報紀律

1. **先給讀到的流程**（文字流程圖），再給問題清單。使用者要先確認我讀對了
2. **問題依嚴重度排序**：斷圖/孤島 > 流程語意缺口 > 機器可讀性
3. **區分「圖的問題」與「我的演算法的問題」**。雷 5、6 都曾讓我誤報給使用者。不確定時先說「這是我的推測歸屬，請你確認」，不要直接斷言圖錯了
4. **不要自己改圖**，除非使用者明講。列出問題讓使用者決定
5. 使用者修完再給新檔時，**明確講「這版修好了什麼、還剩什麼」**，不要從頭重講一遍

## 要餵給機器時（轉 LangGraph / spec / 程式碼）

視覺對齊的註解**能自動歸屬，但靠版面規律**；使用者一搬版面就會歸錯。要徹底穩定，請使用者改用兩者之一：

- **群組化**：步驟與其註解框選 → `Ctrl+Alt+G`，或把步驟設成 Container → 解析時有 parent 關係
- **自訂屬性**（最乾淨）：選中步驟 → 右鍵「編輯資料」→ 加 `輸入`/`驗收條件`/`用途` 欄位 → 存成 `<object>` 屬性，解析器的 `attrs` 直接讀得到

另外提醒：流程圖常混著**控制流**（誰接誰）與**資料流**（誰用誰的產出）。只產出文件、不影響流程走向的節點（out=0）不是死路，轉換時應放進 state 而非控制流。

## 常見錯誤

| 做法 | 為什麼錯 |
|:--|:--|
| 直接 `cat` 大檔或壓縮檔 | 亂碼、浪費 context |
| 只看 `.png` 截圖 | 抓不到精確的節點/連線關係，只能目視 |
| 用 `print` 輸出中文報告 | Windows cp950 亂碼 |
| 看到 `[用途]` 離菱形近就歸給菱形 | 雷 5 |
| 報告「圖斷成 N 塊」沒排除註解 | 雷 6 |
| 斷言「這個方塊畫錯了」 | 先看 `style`，可能是脫鉤標籤而非使用者畫錯 |
