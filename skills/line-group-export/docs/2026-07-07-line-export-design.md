# LINE 群組訊息匯出自動化 — 設計文件

日期：2026-07-07

## 背景與目標

「LINE 群組每日訊息摘要自動化」原始需求分兩段：第一段（匯出）與第二段（處理/摘要）。第二段已用 `line-group-daily-report` skill 實作完成。本文件為第一段（匯出）的設計。

目標：自動化「模擬操作 LINE 桌面版 UI，匯出指定群組聊天記錄到固定資料夾」這件事，取代目前每天手動操作的流程。

## 前提限制

- LINE 桌面版（Windows）已登入，且在背景執行（工作列上可找到圖示）。
- 不處理登入流程、LINE 未安裝或未啟動的情境。
- 目標匯出資料夾為既有的 `C:\Users\lithoshu\Desktop\Line社群訊息紀錄`，LINE 已對每個對話記住此路徑，執行「儲存聊天」時可直接「存檔」並「覆蓋」而不需重新選擇路徑。

## 架構總覽

新增 Claude Code skill：`line-group-export`。

- 位置：`C:\Users\lithoshu\.claude\skills\line-group-export\`
- `SKILL.md`：觸發詞「LINE匯出紀錄」，描述完整操作流程供 Claude 依循執行。
- `LineExportHelper.ps1`：PowerShell 輔助函式庫，提供：
  - 尋找/前景化 LINE 主視窗，回傳視窗 rect（位置+大小）。**實作時發現** LINE 常同時開著多個聊天室頂層視窗，`Get-Process` 的 `MainWindowHandle` 不保證是主視窗，因此新增 `Find-WindowByExactTitle`，改用 UI Automation 精準比對視窗標題「LINE」來定位主視窗。
  - 螢幕截圖到檔案
  - 在指定螢幕座標模擬滑鼠點擊
  - 用 UI Automation（`System.Windows.Automation`）尋找並觸發原生對話框上的按鈕（例如「存檔」「是」），依控件名稱而非座標定位，避免座標/DPI 問題
  - 輪詢目標資料夾中特定檔案，偵測檔案大小/最後修改時間穩定（用來判斷下載完成，取代視覺讀取「100%」）

**視覺判斷（決定下一步要點哪裡、目前群組清單有哪些）由 Claude Code 本身完成**：用 PowerShell 截圖 → Read 工具查看 → 判斷座標 → 呼叫 helper 函式執行點擊。不需要額外的 Anthropic API Key，不需要 Python，不引入 pyautogui / pywinauto。

**觸發方式**：手動觸發（使用者輸入「LINE匯出紀錄」）。不含 Windows 工作排程器排程（見「未來擴充」）。

**與既有摘要流程的關係**：匯出成功後自動接續執行既有 `line-group-daily-report` skill 的摘要邏輯，使用者一句話完成「匯出 + 日報」。

## 元件與流程

### Step 0 — 校準

用 PowerShell（`LineExportHelper.ps1`）尋找 LINE 主視窗（依 process/window class，非寫死座標）；若視窗不在前景，點擊工作列圖示喚醒/前景化；讀取當下視窗位置與大小（rect）。之後所有點擊座標均以「相對此 rect 的偏移量」計算，而非螢幕絕對座標，讓視窗位置/大小變動時仍可正確對應。

### Step 1 — 定位「自動化」分類 tab 並讀取群組清單

截圖 → Claude 用 Read 查看，確認「自動化」tab 位置並點擊；再截圖一次，讀出目前分類下所有可見群組名稱，列為本次待處理清單。

限制（v1）：假設一畫面可完整顯示所有群組，不支援捲動。

### Step 2 — 逐一處理群組（迴圈）

對清單中尚未處理的第一個群組，依序執行：

1. 點擊該群組名稱（座標來自視覺判讀）
2. 截圖確認聊天視窗已開啟
3. 點擊右上角「...」按鈕（相對視窗右上角的偏移量，執行前先截圖驗證偏移是否吻合）
4. 點擊「儲存聊天」選單項
5. 「另存新檔」對話框出現 → 截圖判讀「存檔」按鈕座標並點擊；「是否覆蓋」對話框出現 → 截圖判讀「是」按鈕座標並點擊

   **實作時發現**：LINE 的「另存新檔」與「是否覆蓋」對話框雖然外觀模仿 Windows 標準樣式，但實際上是 LINE 自己畫的介面，完全沒有串接 UI Automation（掃描不到任何按鈕元件）。原設計假設可以用 UI Automation 精準定位這兩個對話框按鈕的做法不可行，已改為與其他步驟一致，全部用截圖 + 視覺判讀座標的方式點擊（已在 2026-07-07 實測驗證可行）。`Invoke-DialogButtonClick`（UI Automation 版本）保留在 helper script 中、程式碼本身已驗證可用於真正的原生對話框，但目前的 LINE 匯出流程不會用到它。

   **後續加速（2026-07-07 二次實測）**：跑了兩輪、共 10 個群組後發現，「存檔(S)」按鈕的位置其實跟觸發它的聊天視窗 rect 有穩定的偏移關係，「是(Y)」（覆蓋確認）按鈕則落在幾乎固定的螢幕絕對座標。已將這兩組座標寫入 `SKILL.md`，往後執行直接套公式盲點，不用每次截圖裁切確認，省下這兩步的視覺判讀時間；`Wait-FileStable` 繼續作為失敗安全網。
6. **完成偵測**：輪詢目標資料夾中對應檔名的 `.txt`，直到檔案大小/最後修改時間連續數次無變化（含 timeout），判定下載完成
7. 點擊右上角「X」關閉聊天室
8. 標記該群組完成；重新截圖讀取目前可見清單，取「尚未處理」中的下一個群組（因群組排序會隨最近訊息變動，每輪重新視覺判讀，不假設固定順序）

### Step 3 — 收尾

所有目標群組處理完畢後，輸出本次執行摘要（成功/失敗各幾個、失敗原因），接著自動觸發既有 `line-group-daily-report` 摘要流程。

## 錯誤處理

- 任一群組在任一步驟失敗或逾時 → 跳過該群組，記錄失敗原因，繼續處理下一個群組，不中斷整體流程。
- 若「自動化」tab 本身找不到（LINE 未開啟、UI 改版、tab 位置不明等）→ 視為整次執行失敗，記錄並停止，不誤觸其他群組。

## 紀錄（Logging）

每次執行寫入 `line-group-export\logs\YYYY-MM-DD_HHmm.log`，內容包含：
- 本次識別到的群組清單
- 每個群組的成功/失敗狀態與失敗原因
- 總耗時

執行結束後，Claude 會在對話中直接口頭總結成功/失敗清單；log 僅在需要追查細節時查閱。

## 已知限制 / 未來擴充

- v1 不支援捲動；群組數超出單一畫面高度時需另外設計捲動邏輯。
- 僅支援手動觸發，未串接排程器。若未來需要「每天定時自動觸發」：
  - 建議做法：Windows 工作排程器定時呼叫 headless `claude -p "LINE匯出紀錄"`，沿用同一套 PowerShell 邏輯（不需重寫，因為視覺判斷仍由 Claude 完成）。
  - 若進一步想做到完全不呼叫 AI 的排程自動化（零 token 成本、更快），屆時建議改用 Python + `pywinauto`，透過 UI Automation tree 以控件名稱定位取代視覺判讀。
- 對話框按鈕文字（存檔／是）假設為繁體中文 LINE 介面預設文字；若介面語言或版本改變按鈕文字，需調整 helper script 中的控件比對邏輯。

## 測試方式

實作完成後，於使用者在場、螢幕可見的情況下，實際觸發「LINE匯出紀錄」執行一次，逐步確認：

- 視窗定位與 rect 計算是否正確
- 「自動化」tab 群組清單讀取是否正確
- 每個群組是否成功存檔並正確覆蓋既有檔案
- 刻意製造一個失敗情境（例如中途關閉某個聊天室干擾），確認 log 正確記錄且流程未中斷
- 確認全部群組處理完後，自動接續「LINE群組日報」摘要流程正常運作
