# 任務: 打磨階段設計(第 $round_no 輪, 產出到 `$round_dir/game/`)

你是遊戲設計師。玩法已經定案, 打磨階段只做**一款**, 讓它成為完整的小遊戲: 有關卡、難度曲線、音效。打磨固定在 `$project/$round_dir/game/` 這一個資料夾裡迭代。

## 請讀取
- `$project/idea.md`、`$project/hypotheses.md`
- 上一輪的回饋 `$project/$prev_round/feedback.md`
- 底版:
  - 上一輪就是 `$round_dir`(打磨的後續輪次): 底版就是 `$project/$round_dir/game/` 本身, **就地修改**
  - 上一輪是深掘: 回饋與驗證文件指出的勝出款
  - 上一輪是 `polish-<數字>`(舊版編號資料夾): `$project/$prev_round/game/`
- 底版的 spec.md、interface.json(底版來自深掘時另有 guide.md, 只當教學內容的參考)
- 難度分析 `$project/$prev_round/difficulty.md`(有的話)
- `$studio_refs/guide-principles.md` — 玩家說明的寫法原則, 打磨用來寫教學提示的文字(短、以圖為主、講玩家會做的動作)

## 要做的事

1. 底版在別的資料夾時: 把底版款的**整個資料夾**(spec.md、interface.json 與 `game/` 下全部程式、美術、音效; guide.md 不搬)複製到 `$project/$round_dir/game/`, 之後美術、RD、音效都在既有產物上修改而不是重做。底版就是本資料夾時不用複製; 但若本資料夾還留著舊的說明頁(guide.md、interface.json 的 `guidePages`), 刪掉 guide.md 與 `guidePages`, 改寫成開始畫面 + 新手教學
2. 以底版為基礎(沿用它的規則與 interface.json, 只做必要增修), 改寫 `$project/$round_dir/game/` 下的 spec.md 與 interface.json
3. spec.md 在探索 / 深掘的章節之外, 要有下列章節(底版已有就更新):
   - `## 開始畫面`: 開場顯示什麼、用哪個輸入開始(同一種輸入)。**打磨沒有說明頁**, 開始後直接進遊戲
   - `## 新手教學`: 教學嵌在遊戲流程裡, 手把手帶玩家進入狀況。寫成一張表, 每個階段一列:
     | 階段 | 出現時機(第幾關、什麼條件) | 提示內容(文字 + 按鍵圖示) | 位置(貼著哪個物件) | 完成條件(玩家做到什麼) | 完成特效 |
     原則: 一次只教一件事; 每個新操作、新能力、新機關在**第一次出現**的地方教, 不提前、不集中在開頭; 第 1 階段從最基本的操作教起(例: 左右與跳, 每個鍵都按過才算完成); 完成條件要是玩家實際做到的動作, 不是按「下一步」; 已完成的階段不再出現, 重來不重置; 每個完成條件都拿規格數值做一次整數驗算, 確認玩家照教學做一定達得到(例: 血量 6、每下傷害 2, 永遠停在 2 → 0, 落不進「≤ 1.8 才能收服」); 提示泡泡 / 箭頭的尖端座標由被指元件的版位推出來(兩者寫在不同段落時互相驗算), 泡泡本體不壓到角色與遊戲區; 完成動作本身會換畫面的階段(例: 按 Z 出發、走下樓梯), 寫明完成特效在哪個畫面播, 或換畫面延後到特效播完。interface.json 的 draw 清單要有 `drawTitle` 與 `drawTutorial`, 並寫清楚 drawTutorial 的 state 欄位(階段、文字、按鍵、已按過的鍵、完成特效進度、位置)

   - `## 關卡`: 關卡數與每關的參數(表格), 難度怎麼爬升
   - `## 埋點`: 每局結束自動下載 JSON(檔名 `gamelog-<專案資料夾名>-<YYYYMMDD-HHMMSS>.json`), 列出事件與欄位; 至少能算出每關通過時間、失敗次數、卡關位置, 以及每個教學階段出現與完成的時間
   - `## 音效清單`: | 事件 | 何時發生 | 要讓玩家感覺到什麼 |, 另列背景音樂與靜音操作(同一種輸入); 同一瞬間會一起觸發的事件(例: 倒下與地下城結束)寫明是疊著播還是只播哪一個
4. interface.json 要有 `"sounds": [事件名...]` 與 `"music": [曲名...]`; 新增物件照規則補 draw 函式; 改既有函式的 state 欄位名時, 在 notes 列出「舊名 → 新名」對照(美術沿用舊版會讀到不存在的欄位, 悄悄退回預設值看不出錯); 寫完逐項自查(美術與 RD 各自讀介面, 定義模糊就會各自解讀): (1) 有經過時間的狀態(預警、倒數、冷卻、蓄力、一次性特效, 以及常駐元素在事件當下「彈一下 / 閃一下」)同時給總長欄位, 並寫明閒置時的值且不能等於起始值(例: 閒置時已過秒數 = 總長), 或另給「是否在播」欄位 (2) `size` 依種類 / 依畫的區域有不同大小時分開給, 不只照最常見的一種填; notes 要求畫到框外的東西, size 要涵蓋或寫明例外, 兩處對過一致; 過渡動畫的放大或位移(彈一下、浮起、震動)也算畫到框外, 寫明放大的是整塊還是只有內容 (3) 有寬度的邊(判定的環、波、線, 以及畫面上的柔邊、光暈、外框)寫明給的尺寸指外緣、中線還是內緣 (4) 位置固定的畫面元件(HUD、面板、按鈕、卡片)state 帶 x, y 由 RD 傳入, 或在 notes 寫明固定版位, 不只給 size; 函式裡的子部件(例: 魔物頭上的怒氣條)寫明在本體框內或框外, 以及相對中心的座標 (5) 說明頁與新手教學以外的畫面(標題卡、結算、HUD 提示等), 每段文字寫明歸美術畫還是 RD 畫; 說明頁與新手教學的分工已固定在美術 / RD 任務裡, 介面不另寫(文字歸屬清單不列說明頁繪製函式), 免得兩邊衝突 (6) 有作用範圍的物件(含倒數後才生效的)要有能畫出範圍的函式或狀態; 會移動到別區(例: 闖進觀眾席)的狀態寫明要畫在該區物件之上 (7) 陣列或格位用「第 N 項」描述時, 寫明從 0 還是 1 起算 (8) 新增或改名的欄位會改變共用的畫法(例: 越深的樓層地板越暗)時, 找出所有畫同一種東西的函式(例: 出口、泉水等自己畫一塊地板的物件)都補上這個欄位 (9) 替既有物件的新狀態指定顏色時, 先對過同物件其他狀態與畫面上已有的顏色, 撞色就只寫意圖、顏色交給美術 (10) 清單或陣列欄位寫明長度範圍(含 0)與放不下時的規則(全畫並改版面 / 第 N 項後收成「+N」/ 捲動)
5. 回饋若有難度意見, 調整關卡參數; 在 `$project/hypotheses.md` 修訂紀錄加一行說明本輪改了什麼
6. spec.md 開頭加 `## 本輪改動`: 條列相對上一版改了什麼, 讓美術、RD、音效知道該動哪裡

`$project` 底下其他輪次的資料夾(explore-*、deepen-*、polish-<數字>)會在你交稿後被刪除, 需要的東西一定要搬進 `$round_dir/game/`。
