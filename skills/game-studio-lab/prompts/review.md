# 任務: 檢討假設($round_dir)

使用者試玩了本輪遊戲並接受訪談。依回饋更新玩法驗證文件。

## 請讀取
- `$feedback` — 本輪訪談整理(使用者的原話與感受)
- `$project/hypotheses.md` — 玩法驗證文件
- `$project/$round_dir/*/spec.md` — 本輪各款規格, 了解每款實際做了哪些機制
- 打磨階段另讀 `$project/$round_dir/logs/` 下的試玩紀錄 JSON(有的話)

## 要做的事

1. 本輪「驗證於 $round_dir」的每條假設, 依回饋判定:
   - **成立**: 使用者的感受與預期相符 → 留在表上, 並把機制寫進「機制清單: 保留」(正面體驗)或「避開」(負面體驗成立 = 這機制確實帶來壞體驗)
   - **推翻**: 使用者明確說沒有這種感受, 或感受相反 → 從假設表刪除, 修訂紀錄寫一行「刪除 Hxx: 機制 → 體驗, 原因」
   - **不確定**: 回饋沒提到, 或感受模糊 → 留表, 狀態改「不確定」, 下一輪換做法再驗
2. 回饋中**使用者明確表達**的想要 / 不要的體驗, 寫進「已確認的體驗」; 只寫有回饋為證的, 不要推測
3. 回饋提到的、不在假設表上的新發現(例: 某機制意外帶來樂趣), 新增為假設並直接標成立或推翻
4. 修訂紀錄加一行: `$round_dir 檢討: 成立 Hxx...、推翻 Hyy...、不確定 Hzz...; 使用者選擇 $choice`
5. 打磨階段且有試玩紀錄: 另寫 `$project/$round_dir/difficulty.md`, 分析每關通過時間、失敗次數、卡關位置, 指出難度曲線哪裡太陡或太平

判定時以使用者的原話為準; 判斷依據寫進修訂紀錄, 讓人看得出為什麼。保持文件精簡清楚: 推翻的從表上拿掉, 不要留在表上打刪除線。

## 回報
成立 / 推翻 / 不確定各幾條、各是哪些, 已確認的體驗有什麼變化。
