# 任務: 視覺設計 — 挑底版與列出核心視覺元素

你是遊戲設計師。深掘已結束, 下一步是打磨。打磨前先把這款遊戲的**核心視覺元素**列出來, 使用者確認後美術會為每個元素各出 3 個方向不同的方案讓使用者挑, 打磨照挑中的方向做。這一步只列清單, 不畫圖、不改遊戲。

## 請讀取
- `$project/idea.md`、`$project/hypotheses.md`(特別是狀態「成立」的「機制 → 體驗」)
- 深掘最後一輪的回饋 `$project/$round_dir/feedback.md`
- `$project/$round_dir/` 底下各款的 spec.md 與 `game/art/style.md`

## 要做的事

1. **挑底版**: 依回饋與 hypotheses.md 指出的勝出款, 決定哪一款進打磨(跟打磨設計挑底版的判斷相同, 提前在這裡做)。這款的 `game/art/art.js` 是美術畫方案的基礎
2. **列元素**, 寫成 `$visual_dir/elements.md`:
   - 固定類: 開始畫面(以遊戲主視覺呈現的小動畫, 不演玩法)、主角、介面風格(HUD、按鈕、字)
   - 依玩法類: 和核心玩法綁在一起、玩家一直會看到的動態或特效。從成立的假設與規格的核心操作找(例: 節奏遊戲的物件隨拍呼吸、踩中拍點的特效; 平台跳躍的起跳落地、觸發機關)
   - 每個元素要是玩家會明顯注意到、方向不同會改變遊戲感受的東西; 次要物件(一般背景裝飾、少見的道具)不列
   - 元素多到使用者一次看不完時(大約超過 8 個), 合併相近的或只留最重要的, 在回報寫明刪了什麼
3. 格式(照抄結構, 代號用英文小寫、數字與連字號, 類型只能寫 靜態 或 動態):

```
底版: <深掘資料夾>/<款>          (例 deepen-2/game-b)

## title — 開始畫面
類型: 動態
內容: 以主視覺呈現的大而顯眼小動畫, 底下一行「按任意按鍵開始遊戲」
為什麼是核心: 玩家第一眼看到的畫面

## hero — 主角
類型: 靜態
內容: ...
為什麼是核心: ...
```

- 「內容」寫這個元素在遊戲裡是什麼、出現在哪、要表達什麼(給美術看), 不寫具體方案(方案是美術的事)
- 動態元素寫清楚是什麼時候觸發、大約多長(例「每拍一次, 約 0.3 秒」)

不改任何其他檔案。

## 回報
底版選了哪款、為什麼; 列了哪些元素(各一句); 合併或刪掉了什麼。
