# interface.json 寫完自查

設計節點寫完 interface.json 後逐項對過。美術與 RD 同時各自讀介面, 定義模糊就會各自解讀, 接起來才出錯。

1. 有經過時間的狀態(預警、倒數、冷卻、蓄力、一次性特效, 以及常駐元素在事件當下「彈一下 / 閃一下」)同時給總長欄位, 並寫明閒置時的值且不能等於起始值(例: 閒置時已過秒數 = 總長), 或另給「是否在播」欄位
2. `size` 依種類 / 依畫的區域有不同大小時分開給, 不只照最常見的一種填; notes 要求畫到框外的東西, size 要涵蓋或寫明例外, 兩處對過一致; 過渡動畫的放大或位移(彈一下、浮起、震動)也算畫到框外, 寫明放大的是整塊還是只有內容
3. 有寬度的邊(判定的環、波、線, 以及畫面上的柔邊、光暈、外框)寫明給的尺寸指外緣、中線還是內緣
4. 位置固定的畫面元件(HUD、面板、按鈕、卡片)state 帶 x, y 由 RD 傳入, 或在 notes 寫明固定版位, 不只給 size; 函式裡的子部件(例: 魔物頭上的怒氣條)寫明在本體框內或框外, 以及相對中心的座標
5. 說明頁與新手教學以外的畫面(標題卡、結算、HUD 提示等), 每段文字寫明歸美術畫還是 RD 畫; 說明頁與新手教學的分工已固定在美術 / RD 任務裡, 介面不另寫(文字歸屬清單不列說明頁繪製函式), 免得兩邊衝突
6. 有作用範圍的物件(含倒數後才生效的)要有能畫出範圍的函式或狀態; 會移動到別區(例: 闖進觀眾席)的狀態寫明要畫在該區物件之上
7. 陣列或格位用「第 N 項」描述時, 寫明從 0 還是 1 起算
8. 新增或改名的欄位會改變共用的畫法(例: 越深的樓層地板越暗)時, 找出所有畫同一種東西的函式(例: 出口、泉水等自己畫一塊地板的物件)都補上這個欄位
9. 替既有物件的新狀態指定顏色時, 先對過同物件其他狀態與畫面上已有的顏色, 撞色就只寫意圖、顏色交給美術
10. 清單或陣列欄位寫明長度範圍(含 0)與放不下時的規則(全畫並改版面 / 第 N 項後收成「+N」/ 捲動)
