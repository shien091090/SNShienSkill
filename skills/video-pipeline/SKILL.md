# video-pipeline

一支影片一個資料夾 `<影片根目錄>\<片名>\`, 畫面是 GSAP 時間軸(`live/film.js`), 逐格渲染成 mp4。使用者在 Artifact 審閱頁點選方案, 我讀選擇、組合、再出下一輪。進度記在資料夾的 `STATUS.md`, 跨 session 靠它接。

細節需要時才讀:
- `references/platforms.md`: 平台 → 比例、安全區、編碼與音量規格
- `references/film-contract.md`: film.js 的寫法與踩過的坑(**寫第一行動畫前必讀**)
- `references/review-page.md`: 審閱頁怎麼改、怎麼發布、怎麼讀使用者的選擇
- `references/audio.md`: 音效與音樂的素材來源、授權、方案與混音

## 每次呼叫的固定開場

1. 拿片名(沒給就問)。影片根目錄: 環境變數 `VIDEO_ROOT` 有設就用它, 沒設用 `E:\Project\Videos`; 兩者都不存在 → 問使用者要放哪, 不自己挑位置。資料夾 = `<影片根目錄>\<片名>`
2. 讀 `STATUS.md`。不存在 → 新影片, 從「需求」開始。存在 → 回報一句「目前在 X 階段第 N 輪, 審閱頁 <URL>」, 問繼續還是回頭改

## 階段 1 需求: 三項必填

開工前**必須**從使用者那裡拿到這三項, 缺任何一項就只問缺的那項, 停在這裡:

| 必填 | 用途 |
|---|---|
| 平台 | 決定比例(見下表), 比例決定每一幀的構圖, 事後不能用裁切補救 |
| 關鍵幀動畫敘述 | 每一幕要演什麼, 是拆關鍵幀的唯一依據 |
| 總影片時長 | 所有關鍵幀時間加總的目標 |

| 平台 | 格式 | 尺寸 |
|---|---|---|
| IG(不論貼文或 Reels) | `sq` | 1080×1080 (1:1) |
| 其他: Threads、TikTok、YT Shorts、網站等 | `por` | 1080×1920 (9:16) |

多個平台跨兩種格式 → 兩種都做, 問使用者哪個是**主格式**(方案都在主格式下挑, 另一個格式在畫面定案後重排版面, 時間點與音軌共用)。

**缺項時不要做的事**(全部等於跳過閘門): 套預設平台或預設時長、自己編關鍵幀內容、「先做個草稿給你看」、從舊專案沿用。使用者說「你決定就好」→ 提出具體建議值請他確認, 他點頭才算拿到。

三項到齊後, 順便問片中要用的素材(LOGO、遊戲截圖、品牌色、字型)放在哪; 素材不擋開工, 沒有的先用色塊佔位並在審閱頁標明。

建資料夾:

```bash
V="${VIDEO_ROOT:-/e/Project/Videos}/<片名>"; mkdir -p "$V" && cp -r ~/.claude/skills/video-pipeline/templates/* "$V"/
cd "$V" && git init && printf 'node_modules/\n.cache/\n.venv/\noutput/\nrenders/\n*.wav\n' > .gitignore
node tools/setup.mjs   # 裝 headless Chrome、puppeteer、Python 音訊套件與 ffmpeg, 寫 video.config.json
```

在 `film.js` 的 `FORMATS` 只留這支影片要出的格式, 主格式放第一個; 寫 `STATUS.md`(格式見文末)。

## 階段 2 畫面方案(第 1 輪)

1. 依使用者的敘述重新拆關鍵幀(可以拆細或合併), 貼成表給使用者確認: 編號、名稱、開始秒數、長度、內容一句話。長度加總 = 總時長。使用者確認才寫程式
2. **每個關鍵幀做 3~4 個方案**(a/b/c/d)。方案之間要是不同的點子(進場方式、運鏡、構圖、節奏), 不是同一招換參數
3. 這階段**不加音效、不加音樂**
4. 每個方案寫完用 `node tools/shot.mjs '{"k3":"b"}' renders/k3b 2.1 2.6` 截幾格自己看過, 確認沒有破圖、文字溢出、元素跑出安全區(`platforms.md`)才發布
5. 改 `live/index.html` 的 ROWS 與 KF_DESC, 發布審閱頁(`review-page.md`), 把網址給使用者

## 階段 3 畫面迭代

使用者說選好了:

1. 用 ArtifactData 讀 `picks/current`, 把結果用中文列回去讓使用者核對(「K3 選 b: 從左側滑入…」)
2. 把選中的方案寫死成新的基準: 刪掉沒選的分支、`OPTIONS` 清空。commit 一次(`git` 就是每輪的備份)
3. 照使用者這輪的指示改:
   - 純改字、指令已經很明確的修改 → 直接改, 不出方案
   - 需要創意判斷的(「活潑一點」「要有蓋印章的感覺」)→ 該幀出 3~4 個方案, 再加一個 `"0"`(審閱頁顯示「原」= 目前的樣子)
4. 時長守住: 改完總長和使用者要求的差超過 0.5 秒 → 告訴使用者差多少、建議從哪幾幀調
5. 同一個審閱頁網址重新發布, STATUS.md 記這輪的選擇與改動

重複到使用者明確說畫面定案。有兩種格式時, 定案後再把次要格式的版面排好, 給使用者看一次。

## 階段 4 音效

1. `node tools/sfxcues.mjs audio/cues.json`, 複製一份成 `audio/cues.base.json`(之後重新計時靠它對回舊 id)
2. 依「該有音效的時機」拆, 不是依關鍵幀拆。一個時機可以包含多個 cue(例: 八格依序彈出 = 一個時機, 一組音階)
3. 每個時機 3~4 個方案, 再加 `"x"`(無聲)。素材從免費授權音效庫找, 授權記進 `audio/CREDITS.md`(`audio.md`)
4. 審閱頁切到音效模式(ROWS 清空, 載入 sfxopts.js)。使用者可以在頁面上微調每個時機的音量與早晚, 存在 `sfx/tune`
5. 定案 → 用選擇與微調混出整條音效軌

## 階段 5 音樂

1. 3~4 首候選曲, 每首都先找好進點(主旋律對齊哪個畫面)與結尾, 墊在定案音效底下讓使用者聽(`VID_DOC = "music"`)
2. 使用者選定、需要的話調進點 → 混成最終音軌

## 階段 6 輸出

每個格式各做一次, 規格照 `platforms.md`:

1. `node tools/renderfilm.mjs '{"fmt":"por"}' renders/<片名>-por-silent.mp4 30`
2. `node tools/finish.mjs renders/<片名>-por-silent.mp4 audio/out/final.wav output/<片名>-<平台>.mp4 -14 -1`: 響度正規化、合成、檢查響度、峰值、片長, 有一項不過就 exit 1
3. 自己再看: 片長與使用者要求一致、首尾沒有被切掉; 截幾格聽幾段確認音畫同步
4. 另出一張封面圖 `output/<片名>-<平台>-cover.jpg`(使用者挑一格)
5. 回報檔案位置、片長、響度; STATUS.md 階段改「完成」

## STATUS.md

```markdown
# <片名>
- 平台: IG, Threads  (格式: sq 主 / por)
- 總時長: 30 秒
- 階段: 畫面迭代 第 3 輪
- 審閱頁: https://claude.ai/artifact/...

## 關鍵幀
| # | 名稱 | 開始 | 長度 | 內容 |

## log
- 第 2 輪: K3 選 b, K5 選 a; K6 改字「…」; K8 出 3 個方案(使用者要「更活潑」)
```

需求原文(使用者給的關鍵幀敘述)完整貼在 STATUS.md 的「## 需求原文」, 不改寫。

## 常見錯誤

| 錯誤 | 正確做法 |
|---|---|
| 三項必填沒到齊就開始做 | 只問缺的那項, 停住 |
| 先做 16:9 再裁成 9:16 或 1:1 | 格式在需求階段定, 每一幀照該格式構圖 |
| 3 個方案只是速度或顏色不同 | 每個方案是不同的點子 |
| 第 1 輪就加音效 | 畫面定案前不碰聲音 |
| 使用者選完沒把選擇寫死, 直接疊新方案 | 先寫死成基準、清空 OPTIONS、commit, 再出新方案 |
| 音效依關鍵幀拆 | 依音效時機拆 |
| 每輪換一個審閱頁網址 | 同一個網址重新發布, 網址記在 STATUS.md |
