# 音效與音樂

音效和配樂在**同一輪**給使用者挑(使用者的要求: 不要先定音效再選音樂)。`reference-impl/audio/` 是接力吉尼介紹影片實際用過的腳本(fetchlib.py 是更早的 PVD計畫影片的), 機制可以直接沿用, 但裡面的音效時機、方案內容、檔名都是那支影片的, 每支影片要重寫資料部分:

| 檔案 | 做什麼 | 要重寫的部分 |
|---|---|---|
| `fetchlib.py` | 從免費音效庫抓候選, 寫 `lib/catalog.json` 與 `lib/CREDITS.md`; `--music` 抓配樂 | 要抓的分類與關鍵字 |
| `moments.py` | 音效時機與每個時機的方案 | 整份 `MOMENTS` |
| `libmix.py` | 依選擇與微調混音; `--options` 輸出每個方案的 wav 與 `sfxopts.js` | 路徑、音效庫前綴 `K`(`game` = 遊戲自己的音效資料夾) |
| `music.py` | 配樂分段(可只一段)、每段候選曲的進點與淡入淡出; `--options` 把每段當成一列**接在音效列後面**(先跑 libmix `--options`); 不加參數 = 音效軌 + 選定配樂混成 `out/final.wav` | `CUES`(段落、起迄時間、候選曲) |

複製到影片資料夾的 `audio/`, 用 `video.config.json` 裡的 `python` 跑(系統 Python 在 Windows 預設 cp950, 讀中文路徑或 json 會錯; 自己寫的 Python 一律 `encoding="utf-8"`)。

## 音效方案

- 依「音效時機」拆, 一個時機可以包含多個 cue。例: 八格依序彈出 = 一個時機, 方案可以是「一格一個音、往上爬音階」
- 每個時機 3~4 個方案 + `"x"`(無聲)。方案之間要聽得出差別(材質、音高、疊層數), 不是同一個檔換音量
- 方案的 wav 先混好音量(以預設混音的整體增益為準), 頁面上直接播就是最終聽到的大小
- 時間點對齊: 揮動、咻聲這類有起音的聲音, 把**最大聲那一刻**對在 cue 上, 不是檔案開頭
- 畫面事件不在 cue 那一刻發生時(例: 碎片落下 0.45 秒後才碎), 方案要帶偏移
- 重新計時後, 新的 `cues.json` 依「同種類第 n 個」對回 `cues.base.json` 的舊 id, 使用者的選擇才不會掉

## 遊戲原音

遊戲畫面上的動作(跳、落地、踩頭、死亡、過關)優先出一個「`0` = 遊戲原音」方案: 檔案直接用遊戲的音效資料夾(libmix 的 `game` 前綴), 時間用錄影時記下的音效事件(`events.json`、`.sfx.json`)換算成影片時間放 `cue()`, 聲音和畫面上的動作會完全對齊。

## 混音

- 每層: 修掉開頭靜音 → 裁長度並淡出 → 視需要高通、移調 → 依角色調到目標響度後疊到 cue 時間
- 音效軌整體約 −18 LUFS, 限制器天花板 −3 dBFS(預留 AAC 編碼的過衝)
- 最後的 −14 LUFS 由 `tools/finish.mjs` 統一處理, 混音階段不用追

## 讀選擇

`sfx/current` 裡沒有的列 = 使用者沒點, 頁面試聽時播的是預設(有 `"0"` 用 `"0"`, 否則第一個方案)。寫 `picks.json`、`music.json` 時用同一個預設, 使用者聽到的才等於輸出的; 回報時講清楚「這列沒點, 照試聽的預設 X」。

## 音樂方案

- 3~4 首候選。每首都先找好: 哪一段(避開前奏的吸氣聲、尾奏)、主旋律對齊哪個畫面、在哪裡淡出
- 用拍點偵測(librosa)找小節頭對齊畫面重點; 自動找不準就手動指定進點
- 淡入 1.5 秒、淡出 1.2 秒(sin²); 配樂墊底約 −24 LUFS, 片尾小旋律約 −22 LUFS, 都比音效小
- 配樂和音效同一輪挑: 每段配樂是審閱頁上的一列(`mus1`、`mus2`…), 和音效列一起存在 `sfx/current`; 審閱頁的音檔一律用 **wav** 不用 mp3(mp3 的編碼延遲會讓每個音效晚幾毫秒)
- 使用者想在某個畫面換曲時(例: 「這就對了」之前一段、之後一段), 前一段在切點前 0.1 秒淡出, 後一段用拍點偵測讓重拍落在切點的畫面重點上
- 結尾: 音樂提早結束、最後幾秒沒聲音時, 主動問使用者要不要補一個收尾音效
