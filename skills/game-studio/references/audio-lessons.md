# 音效經驗

只有音效 agent 讀寫。跨遊戲通用, 不寫單一遊戲的素材檔名、音量或事件表 — 那些屬該遊戲的 sound.md。

**為什麼需要這份**: 音效每次上工都是全新 session, 前幾版找過哪些素材站、哪種授權踩過雷、哪種聲音被老闆嫌吵, 一概不傳承。

## 怎麼用

- **開工**: 先讀完本檔。sound.md 的「理念或經驗落實」一節, 寫本檔裡跟本作有關的條目怎麼落實
- **處理回饋(音效修正)**: 每條音效回饋動手前先判定它屬於下面哪一類, 修完後依「怎麼長」回寫

## 怎麼長

- 格式: `(症狀) → (原因) → (解法)`, 附遊戲名與輪次; 來自老闆回饋的附原話
- **必須隔一次實際修正才寫**: 老闆的音效回饋先進該遊戲的 feedback, 走過一次音效修正、真的改過之後, 才把通則寫進來。只聽到一次回饋就寫, 會把「這一輪的個人偏好」誤寫成通則
- 標性質: `辨識`(任何玩家都成立: 聽不聽得出是哪個事件、會不會蓋掉重要的聲音)或 `品味`(老闆個人偏好: 好不好聽、風格)。兩者不混, 品味條目遇到新遊戲時只當參考
- 同一個根因累積到兩條以上、且來自不同事件或不同遊戲時, 可以在本檔最上方提一條「原則」(寫明犧牲與邊界), 形式比照美術經驗的設計理念
