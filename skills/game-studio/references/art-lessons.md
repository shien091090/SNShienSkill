# 美術經驗

只有美術 agent 讀寫。跨遊戲通用, 不寫單一遊戲的版位、色票或尺寸 — 那些屬該遊戲的 style.md。

**為什麼需要這份**: 美術每次上工都是全新 session, 輸入只有 spec.md, 前幾版的版面判斷與踩過的坑一概不傳承。同一個遊戲改版重做四次, 就有四次機會重犯同一個錯。

兩層:
- **設計理念**(上層): 抽象、跨遊戲的判斷準則。回答的是「兩個設計打架時選哪個、為什麼」, 用來處理沒見過的情況
- **經驗**(下層): `(症狀) → (原因) → (解法)`, 是理念的具體實例。每條尾端標它歸屬的理念編號, 可掛多個

## 怎麼用

**開工(完整實作)**: 先讀理念再讀經驗。style.md 必須有「理念落實」一節, 每條「成立」的理念寫一句本作怎麼落實(例: 「P1: 判定線是全畫面唯一有外暈的元素」)。候選理念不必寫, 也不約束設計。

**處理回饋(美術修正)**: 每條美術回饋動手前先回答「這違反了哪條理念」:
- 答得出來 → 該理念底下補一條經驗(或把回饋加進既有經驗的證據), 並檢查它的「邊界」是不是寫得太寬, 讓這次的錯鑽過去了
- 答不出來 → 寫一條新經驗; 若它和既有某條沒掛理念的經驗是同一個根因, 提一條候選理念

**理念衝突**: 依編號順序, 編號小的優先。P0 固定排頭。

## 理念的寫法與升降

每條理念四欄, 缺一欄就還只是口號:
- **理念**: 一句話, 抽象到換一種遊戲類型也能用
- **犧牲**: 遵守它要付出什麼。寫不出代價的不收
- **證據**: 掛了哪些經驗; 來自老闆回饋的附遊戲名與輪次和原話(原話最能擋抽象化走樣); 來自外部準則的標 `外部: <出處>`
- **邊界**: 什麼情況不適用

**兩個驗收問題**, 升格前必須都答得出來:
1. 想像一個完全不同類型的遊戲(卡牌、平台跳躍、塔防), 這條還能下判斷嗎?
2. 面前有兩個版面, 這條能選出一個嗎? 選不出來就是口號

**狀態**:
- `候選`: 證據只有一條, 或還沒通過驗收問題。不約束設計, 只是提醒
- `成立`: 至少兩條經驗、來自兩個不同情境(不同物件、不同介面區塊或不同遊戲)指向同一根因, 且通過驗收問題
- 另標 `跨遊戲: 已驗證 / 未驗證` — 證據是否來自兩個以上的遊戲。未驗證的成立理念照樣約束設計, 但遇到老闆回饋與它衝突時優先懷疑它

**性質**:
- `可讀性`: 對任何玩家都成立(看不看得清、分不分得出、讀不讀得懂)
- `品味`: 老闆個人的美感偏好。看的人固定是他, 所以一樣跨遊戲有效, 但依 P0 排在所有可讀性理念之後; 不可把品味寫成可讀性的鐵律

**來源**:
- 不標: 從本工作室的回饋與實際修正歸納出來的
- `外部`: 從業界既有準則(例: game-ui-design skill)摘錄、已由老闆逐條篩選過的。外部理念一律從候選起步; **升成立只需一條本工作室的經驗(老闆回饋或實際修正)指向它** — 業界已有廣泛證據, 缺的是「在我們的遊戲與老闆眼裡也成立」這一步。外部證據併進既有理念時只當佐證, 不算升格所需的經驗條數
- 外部準則的原文不在本檔依賴範圍內, 本檔已寫全要用的部分; 不要去翻原 skill 補讀

**降格**: 老闆回饋直接和某條成立理念衝突 → 先縮它的「邊界」; 縮不了就降回候選並寫明衝突的回饋。證據不刪。

**同類合併**: 新理念和既有的只差措辭 → 合併, 證據併過去, 不另開編號。編號不重用。

## 設計理念

### P0 辨識度先於好看
- 狀態: 成立(工作室基準, 不經歸納) / 性質: 可讀性 / 跨遊戲: 已驗證
- 理念: 玩家一眼分得出每種物件與它的狀態(可互動 / 危險 / 已用掉), 才輪到美感
- 犧牲: 裝飾、氛圍、畫面的完整感; 常常得接受較單調或較「工程感」的畫面
- 證據: 本檔所有經驗的共同前提
- 邊界: 只在兩者衝突時才適用; 不衝突時照樣要好看

### P1 視覺權重跟著玩家決策的迫切度走
- 狀態: 成立 / 性質: 可讀性 / 跨遊戲: 已驗證(史萊姆擴張、捕泡手)
- 理念: 越接近「玩家此刻要做決定」的資訊越顯眼; 資訊的新舊、演出的華麗程度、系統覺得它多重要, 都不構成加權的理由
- 犧牲: 事件演出(獎勵、升級)不能搶戲, 爽感要從別的地方給(音效、盤面本身的變化), 而不是蓋在決策資訊上
- 證據: 事件提示蓋住常駐資訊、判定線被淹沒、資訊密度逼近上限; 老闆回饋(史萊姆擴張 第 1 輪): 解鎖瞬間側面板「全部疊在一起, 無法辨識」, 事件提示不得覆蓋常駐數值; 老闆回饋(史萊姆擴張 第 10 輪)盤面旁的下次開欄標示「整塊的虛線加上下方的字『下次開這側』, 視覺呈現太強烈, 要再弱化一點」(經驗「貼近物件的重述標示畫成第二份完整讀數」); 捕泡手 v3 建置自查: 網中央的勾叉會蓋住捕捉當幀換上的目標數字(併入經驗「事件提示蓋住常駐資訊」; 屬預防性修正、非老闆回饋, 不據此改跨遊戲標記); 老闆回饋(捕泡手 第 2 輪)氣泡倒數環改成「一圈 = 這一秒」, 讓重心放在「進度條走完之前趕快凍結這個數字」(經驗「倒數環以總時長為滿, 和中央數字重述同一件事」; 第二個遊戲的老闆回饋, 跨遊戲改為已驗證); 外部: game-ui-design(資訊層級裡背景與地形最低調, 不搶戲)
- 邊界: 遊戲暫停或結算畫面沒有即時決策, 這時事後回饋可以升為最高層

### P2 規則上存在的東西, 畫面上就必須存在
- 狀態: 成立 / 性質: 可讀性 / 跨遊戲: 未驗證
- 理念: 會影響結果的規則狀態(歸屬、零效果、隱藏計數)都要有可見的樣子; 玩家看不到的規則, 在他眼裡不是不存在就是 bug
- 犧牲: 畫面元素變多, 必須靠 P1 排層級來撐住密度
- 證據: 零效果事件無聲跳過、整組一起動的格位沒畫歸屬; 老闆回饋(捕泡手 第 9 輪)「有時候拉著氣泡去碰網, 沒有觸發」, RD 查出 12 例是畫面已貼上、判定還差 1~18 像素(經驗「畫面上的接觸早於判定」: 判定邊界沒有畫在畫面邊界上, 玩家讀成 bug); 外部: game-ui-design(關鍵狀態要隨時一眼可得, 不必暫停或開選單; 可用的操作也要被看見)
- 邊界: 規格刻意要玩家自己推理的資訊(見 P5)不在此列

### P3 一個意義一種長相, 全畫面共用同一本字典
- 狀態: 成立 / 性質: 可讀性 / 跨遊戲: 未驗證
- 理念: 同一個概念在盤面、側欄、提示、結算裡長得一樣; 一種長相也只代表一個意義
- 犧牲: 各區塊不能各自發揮最佳設計, 局部最佳要讓位給全局一致
- 證據: 同概念各區塊用不同顏色、色票與盤面各自畫符號; 說明頁示意圖畫出規則上不成立的盤面; 說明頁沿用舊圖、圖說用詞與遊戲內面板不同(史萊姆擴張 v18 guide 修訂: 「歸零」vs「已達成, 待結算」、已取消的削頂還畫在圖上); 外部: game-ui-design(一致性延伸到操作: 同一按鍵、同一按鈕位置永遠同一意義)
- 邊界: 字典詞只管「屬性」那一層(顏色、無色、凍結、危險); 兩種物件類別不同(能操作的 vs 場景地塊)時, 先用類別層的長相(繪製手法、立體 / 平面、有影 / 無影)分開, 再共用屬性詞, 不能讓共用的屬性詞把兩類物件拉成同一個長相(捕泡手 第 5 輪: 透明氣泡與賦形區共用「空心灰白框 = 無色」, 老闆讀成氣泡與地板太像)

### P4 關鍵區分至少走兩條感知通道
- 狀態: 成立 / 性質: 可讀性 / 跨遊戲: 未驗證
- 理念: 玩家必須分清楚的兩件事, 不能只靠一個維度(只有顏色、只有大小)區分; 至少再加一條(形狀、方向、紋理、動態)
- 犧牲: 設計空間變窄, 每新增一種物件都要同時決定兩個維度
- 證據: 「我造成的」與「系統給的」只靠顏色分、三色以上只用顏色編碼; 老闆回饋(捕泡手 第 5 輪)「染色地板、賦形地板、氣泡三者長得太像, 辨識度很差」, 建議只改氣泡、讓它更有可互動感(經驗「可拿起的物件與地上的地塊同為平面圓」; 跨遊戲標記暫不改: 本條其他支持經驗未標出處遊戲, 待確認後再改已驗證); 老闆回饋(捕泡手 第 8 輪)「很多染色地板的顏色太相近(紅 & 橘、黃 & 橘), 很常沾錯」(經驗「同一關的屬性色為了配合主題色溫挑了鄰近色相」: v14 每關 4 色灰階都拉開了, 同一關色相最近只差 27°~46°); 外部: game-ui-design(色覺異常約佔男性 8%, 紅綠最常撞; 聚焦標示不能只靠變色)。**衝突回饋(已縮邊界, 證據保留)**: 老闆回饋(史萊姆擴張 第 5 輪)「方塊辨識同時提供了形狀跟顏色……我覺得很多餘, 這個只是 prototype 而已, 不需要考慮色盲的情況, 只需留顏色就好」
- 邊界: 只用在玩家必須區分的東西; 純裝飾不需要。**算不算一條通道, 以一眼 / 縮圖的尺度判: 只有近看才看得出的細節差(一小塊高光、外圈一條細環)不算**(捕泡手 第 5 輪: v10 自認氣泡與地塊靠「高光 + 壽命環」分開, 老闆仍讀成三者太像)。**老闆明言不考慮色覺異常的 prototype 階段, 「為色弱加的第二通道」不適用**(例: 色塊上的幾何符號) — 此時顏色編碼只靠色相 + 明度, **兩條都要各自成立: 色相兩兩不落在相鄰色相(約 ≥ 60°, 紅 / 橘 / 黃彼此都算相鄰), 且明度分階(轉灰階仍要分得開); 只過灰階測試不算過**(捕泡手 第 8 輪: v14 照舊邊界只驗了灰階, 琥珀與黃綠只差 27° 仍被讀成同一色); 但「兩種語意不同的事件 / 狀態」(我造成的 vs 系統給的、要動 vs 不動)仍要兩條通道, 那不是為色弱而是為一眼分辨

### P5 畫現況, 不畫未來
- 狀態: 候選(證據一條) / 性質: 可讀性 / 跨遊戲: 未驗證
- 理念: 美術只呈現已確定的狀態, 不替玩家做規格沒要求的推算
- 犧牲: 放棄一些「看起來很貼心」的輔助
- 證據: 把落點試算畫成現況讀數
- 邊界: 規格明文要求的預測性提示(落點陰影等)照畫

### P6 標籤不能比它描述的東西更顯眼
- 狀態: 候選(證據一條) / 性質: 可讀性 / 跨遊戲: 未驗證
- 理念: 數字、符號、徽章是附屬在物件上的, 讀完標籤後物件本身的顏色與形狀仍要一眼可辨
- 犧牲: 標籤要縮小、退到角落, 第一眼可能不容易讀
- 證據: 盤面標示置中蓋住格位本身
- 邊界: 物件本身無資訊量時(例如空格上的倒數), 標籤可以是主體

### P7 每個元素都要掙得它的版面
- 狀態: 成立(史萊姆擴張 第 5 輪升格) / 來源: 外部 / 性質: 可讀性 / 跨遊戲: 未驗證
- 理念: 上畫面前先問「玩家現在需要它嗎?」「拿掉它, 玩家看本體還讀得出嗎?」, 答不出需要、或本體已讀得出, 就不放, 或改成需要時才出現
- 犧牲: 放棄「資訊齊全」的安心感; 一些好看的裝飾性資訊會被砍; 重述型的標籤(數字、字樣、符號)對新手的第一眼輔助也一起砍
- 證據: 外部: game-ui-design(Every element must earn its screen space、Cluttered HUD); 經驗「本體已一眼可讀的資訊再重述」; 經驗「說明頁圖說把圖已畫出來的規則再寫一遍」(史萊姆擴張 v19/v20 guide 修訂, 說明頁情境); 老闆回饋(史萊姆擴張 第 5 輪)三條同源: 團顆數「玩家自己肉眼一眼就能看出來的事情, 再另外又給提示反而會讓人覺得畫面很花更難識別」、預覽的「含重力球」字樣「很多餘, 因為方塊裡就有重力球的圖示了」、方塊的形狀符號「『藍色』跟『正方形』兩種完全等價的辨識手法, 我覺得很多餘」; 老闆回饋(史萊姆擴張 第 8 輪)兩條: 「新任務」橫幅要拿掉(「左上角任務面板就會換成新任務, 玩家已經知道」), 面板標籤「做什麼 / 得到什麼 / 還差多少」改「目標 / 獎勵 / 剩餘」(「用字越少越好」); 老闆回饋(史萊姆擴張 第 9 輪)說明第 3 頁「『下次開這側』的圖整個拿掉」「『做到之後』的演示完全不用。每個任務的獎勵都不一樣, 不需要只說明其中一種」(經驗「說明頁的圖放了不是這一頁要教的東西」); 老闆回饋(史萊姆擴張 第 10 輪)盤面上重述面板讀數的「下次開這側」框 + 字「太強烈, 要再弱化」(經驗「貼近物件的重述標示畫成第二份完整讀數」); 老闆回饋(史萊姆擴張 第 11 輪)「主畫面上的『頂線』字樣有點多餘, 可以直接拿掉」(經驗「本體已一眼可讀的資訊再重述」, 沿用多版的舊標籤); 老闆回饋(捕泡手 第 2 輪)倒數環以 12 秒為滿、重述中央數字已給的總剩餘(經驗「倒數環以總時長為滿, 和中央數字重述同一件事」, 圖形版的重述); 老闆回饋(捕泡手 第 9 輪)「不太喜歡對到拍子時的氣泡表現(氣泡旁類似對話框的 icon 與下方 3 個點點)」: 3 個拍點重述了音波弧組數已給的級數、沾上標籤重述了氣泡本身剛換上的顏色(經驗「回饋的級數與結果值掛在物件旁」)
- 邊界: 規則狀態不因此隱藏(P2 優先); 能砍的是決策用不到的資訊、裝飾, 以及本體已經表達過的重述

### P8 動態是溝通, 不是裝飾
- 狀態: 候選 / 來源: 外部 / 性質: 可讀性 / 跨遊戲: 未驗證
- 理念: 每個動畫都要說得出它在告訴玩家什麼; 動得越多, 每個動作分到的注意力越少
- 犧牲: 待機動畫、呼吸光、背景流動這類「讓畫面活起來」的東西要有理由才留
- 證據: 外部: game-ui-design(Animation is communication, not decoration; Motion guides attention, excess motion kills it); 經驗「物件換位時只在新位置畫出場提示, 玩家視線還停在舊位置」(捕泡手 v10 建置設計判斷, 非老闆回饋, 不算升格證據: 換位掃光是用動態帶視線的正例, 同時標出它是全場唯一的大動態)
- 邊界: 盤面上的慶祝演出(爽感)本身就是在溝通「你做到了」, 屬於有理由的動態

### P9 以最混亂的那一刻驗收
- 狀態: 成立(捕泡手 第 7 輪升格: 外部理念 + 一條老闆回饋) / 來源: 外部 / 性質: 可讀性 / 跨遊戲: 未驗證
- 理念: 可讀性以盤面最滿、事件最密集、演出正在播的時候為準, 不以開局的乾淨畫面為準
- 犧牲: 乾淨畫面下可能顯得過度強調(描邊太重、對比太硬)
- 證據: 外部: game-ui-design(Clarity in chaos、Test on the worst target device); 老闆回饋(捕泡手 第 7 輪)「沾地形目前沒有任何回饋; 場上混亂、氣泡一大堆時, 很難看清楚自己有沒有沾對」(經驗「貼在物件上的回饋只用物件尺寸級的細環」)。驗收: 塔防滿場敵人時「這座塔剛升級」的提示, 塔身換色 vs 塔上方浮一個帶框圖示, 以滿場截圖選得出後者; 卡牌遊戲連鎖結算時每張卡的增益標示同理
- 邊界: 無

### P10 可讀性不能假設背景固定
- 狀態: 候選 / 來源: 外部 / 性質: 可讀性 / 跨遊戲: 未驗證
- 理念: 文字、數字、標示壓在任何可能出現的底色上都要讀得到; 用描邊、陰影、底板至少一種保證, 不靠「這裡剛好是暗的」
- 犧牲: 每段文字多一層處理, 畫面較「硬」
- 證據: 外部: game-ui-design(No Text Outline Or Shadow、Readability Under Motion); 經驗「換皮把背景調亮」(捕泡手 v15 建置截圖自查, 非老闆回饋, 不算升格證據: 亮邊加黑襯底、氣泡加深色外描)
- 邊界: 底色被規格保證永遠不變的區塊(純色側欄)可以只靠對比度

### P11 常駐資訊的位置固定
- 狀態: 候選 / 來源: 外部 / 性質: 可讀性 / 跨遊戲: 未驗證
- 理念: 常駐資訊不跟著震動、演出或盤面變化移動; 要動的是遊戲世界, 不是 UI
- 犧牲: UI 無法參與打擊感演出(畫面震動時 UI 不跟著震)
- 證據: 外部: game-ui-design(Stable anchor points、NEVER apply shake to UI, only world)
- 邊界: 盤面尺寸由規則改變(例: 延展)時, 錨在盤面上的標示跟著盤面走, 但側欄與常駐面板不動

### P12 遊戲區優先於 UI
- 狀態: 候選 / 來源: 外部 / 性質: 可讀性 / 跨遊戲: 未驗證
- 理念: 玩家視線所在的區域(盤面、落點、正在操作的物件)不壓 UI; 非壓不可就半透明、靠角落、避開操作中的物件
- 犧牲: 事件提示離它描述的東西較遠(與 P19 拉扯, 衝突時 P12 優先)
- 證據: 外部: game-ui-design(HUD Obscures Gameplay、UI Blocking Action); 經驗「動作處的事件回饋蓋住正在操作的物件」(捕泡手 v13 建置截圖自查, 非老闆回饋, 不算升格證據: 回饋不是 UI, 但遮擋的是同一個「玩家視線所在、正在操作的物件」)
- 邊界: 遊戲暫停中、需要玩家做選擇的全畫面介面可以蓋住盤面

### P13 事件要排隊, 不能同時冒出來
- 狀態: 成立(史萊姆擴張 第 8 輪升格) / 來源: 外部 / 性質: 可讀性 / 跨遊戲: 未驗證
- 理念: 事件提示分優先級、同時可見的數量有上限、高優先可插隊, 其餘依序播; 排在後面的進場前, 前一個要先退場
- 犧牲: 低優先事件會延後出現, 與它發生的時點脫鉤; 整段演出變長(史萊姆擴張 v22 的任務過場一次 4~6 秒)
- 證據: 外部: game-ui-design(Notification Queue Management)。與 P1 的「事件提示蓋住常駐資訊」同源 — 同一結算裡連發多個事件時, 就算各自不蓋常駐資訊也會互相疊; 經驗「事件內雖然依序進場, 前一塊不退場就等於同時冒出」; 老闆回饋(史萊姆擴張 第 8 輪)解鎖 + 清色球 + 新任務橫幅三塊資訊「只感覺一堆字冒出來什麼都沒看到就全部消失了」。驗收: 卡牌遊戲的回合結算(抽牌、增益、敵方行動)一樣適用; 兩個版面(三張卡片疊著留到結束 vs 一次一張、前一張退場下一張才進)選得出後者
- 邊界: 規格明定時序的事件演出(例: 延展呈現時長)照規格的時長, 但**同一時段內要不要讓前一塊留著、要不要疊在一起仍歸美術**, 不能拿「規格寫了依序」當成已經排好隊(史萊姆擴張 第 8 輪: 規格寫依序 1.5 秒, 美術讓卡片保留到事件結束, 看起來就是同時)

### P14 頻繁的回饋要合併
- 狀態: 候選 / 來源: 外部 / 性質: 可讀性 / 跨遊戲: 未驗證
- 理念: 同類事件短時間內連發, 合併成一個顯示(+50 與 +30 顯示成 +80), 不洗版
- 犧牲: 失去每一筆的個別回饋
- 證據: 外部: game-ui-design(Notification 合併、Damage Number 群聚, 同時可見 5~6 個為上限)
- 邊界: 只合併同類; 不同類事件合併會違反 P3

### P15 回饋的視覺強度和事件的份量成正比
- 狀態: 成立(捕泡手 第 7 輪升格: 外部理念 + 一條老闆回饋) / 來源: 外部 / 性質: 可讀性 / 跨遊戲: 未驗證
- 理念: 大事件大、小事件小, 分級要一眼可辨; 每個事件都用最強演出等於沒有分級
- 犧牲: 小事件的回饋要刻意做得樸素
- 證據: 外部: game-ui-design(Damage Number 依類型差異化, 爆擊 150% 大小加震動); 捕泡手 v12 建置設計判斷(非老闆回饋, 不算升格證據): 清場(全場事件)用整片內圈地面亮起 + 邊光 + 中央字, 捕捉(單顆事件)維持槽位上的單點白環 + 勾, 份量差用「影響範圍 = 演出範圍」表達; 捕泡手 v13 建置設計判斷(非老闆回饋, 不算升格證據): 規格要求「踩拍回饋明顯高於捕捉、整串再高於踩拍」, 四級排成 捕捉(單條白線環)< 踩拍(半徑 72 粉星芒)< 整串(半徑 132 雙層星芒 + 菱形列)< 清場(整片內圈), 每升一級同時換顏色或形狀、不只放大; 同一套分級也延伸到血條上回命那一段的顏色(白 / 粉 / 粉加粗外光); 老闆回饋(捕泡手 第 7 輪)「踩拍回饋要漸進: 第一次對到拍子小特效, 第二、第三次特效漸強」(經驗「踩拍特效只有一種強度」; 份量隨同一顆上連續對拍次數上升, 演出要跟著分級); 捕泡手 v17 建置設計判斷(非老闆回饋, 不算升格證據): 兩級之間插入新回饋時, 不只靠強度分, 外形與動態也要換(經驗「規格在既有回饋分級的兩級之間插一種新回饋」)。驗收: 平台跳躍的連段踩怪(1 / 2 / 3 連)回饋同理; 兩個版面(每次同一個星芒 vs 弧組數與拍點逐級加一)選得出後者
- 邊界: 無

### P16 有狀態的物件, 每個狀態都要有獨立外觀, 包括過渡狀態
- 狀態: 候選 / 來源: 外部 / 性質: 可讀性 / 跨遊戲: 未驗證
- 理念: 列出物件的全部狀態(未就緒 / 快達成 / 就緒 / 使用中 / 停用)逐一設計; 「快達成了」要有預告, 不要從未就緒直接跳到就緒
- 犧牲: 每個物件的設計工作量變多
- 證據: 外部: game-ui-design(Cooldown Indicator 的五種狀態); 經驗「冷卻中的物件畫了剩餘進度的扇形, 截圖上卻幾乎看不到」(捕泡手 v2 建置自查, 未升格: 只證明停用態會吃掉進度圖形, 還沒有老闆回饋或第二個情境); 經驗「被按住與拖曳中同樣凍結倒數」(捕泡手 v6 建置設計判斷, 非老闆回饋, 不算升格證據); 經驗「規格建議預告用半透明, 但半透明在遊戲內已有別的意義」(捕泡手 v8 建置設計判斷, 非老闆回饋, 不算升格證據); 經驗「事件回饋只畫在物件的某一個狀態下, 規格讓物件在事件當幀就換狀態」(捕泡手 v10 建置自查, 非老闆回饋, 不算升格證據); 經驗「時機類提示只在時刻到了才變, 玩家無法預判下一次」(捕泡手 v13 建置設計判斷, 非老闆回饋, 不算升格證據: 「快到了」的預告用一個連續收攏到判定位置的元素); 經驗「連續量的小幅增減在條上只有幾像素, 亮段又與條本體同色系」(捕泡手 v13 建置截圖自查, 非老闆回饋, 不算升格證據)
- 邊界: 無

### P17 進度類資訊, 圖形與數字分工, 不重述同一刻度
- 狀態: 成立(捕泡手 第 2 輪升格: 外部理念 + 一條老闆回饋) / 來源: 外部 / 性質: 可讀性 / 跨遊戲: 未驗證
- 理念: 進度同時用圖形(條、扇形、環)與數字表達, 但兩者分工: 數字給精確讀數, 圖形給數字給不了的那一段 — 通常是「離下一個會改變決策的刻度還有多遠」; 圖形只是把數字已經給的總量再畫一遍, 等於沒用到第二條通道。達成的瞬間要有獨立的回饋
- 犧牲: 佔用較多版面; 圖形不再能一眼比較「誰總共還剩多少」(那要讀數字)
- 證據: 外部: game-ui-design(Cooldown「Combined (best)」); 經驗「冷卻中的物件畫了剩餘進度的扇形, 截圖上卻幾乎看不到」(捕泡手 v2 建置自查; 只證明圖形本身要讀得到); 經驗「倒數環以總時長為滿, 和中央數字重述同一件事」(老闆回饋, 捕泡手 第 2 輪: 「氣泡外圍的環形進度條改成以每一秒為單位(一圈 = 這一秒), 讓玩家把重心放在『進度條走完之前趕快凍結這個數字』」)。驗收: 塔防技能冷卻顯示「3」秒時, 扇形畫這一秒的剩餘 vs 畫 3 秒總進度, 若決策是「等它跳到 0 再按」, 選得出前者; 卡牌遊戲的回合計時同理(數字給剩幾回合, 圖形給這回合還剩多久)
- 邊界: 版面極度受限時保留數字, 圖形可省; 沒有數字、只有圖形時, 圖形照舊畫總進度; 玩家的決策就是比較總量時(誰先到), 圖形可以畫總量

### P18 重要資訊不能只存在一瞬間
- 狀態: 成立(史萊姆擴張 第 5 輪升格) / 來源: 外部 / 性質: 可讀性 / 跨遊戲: 未驗證
- 理念: 閃過就消失的重要內容(獲得了什麼、改變了什麼、做到會得到什麼), 要能在別處查到(常駐欄或結算畫面)
- 犧牲: 常駐欄或結算畫面要多留位置
- 證據: 外部: game-ui-design(Notification History access、Never lose important info); 經驗「獎勵只在事件裡閃一下」; 老闆回饋(史萊姆擴張 第 5 輪)「解完之後也不知道延伸了什麼」(製作人判讀: 獎勵只在盤面中央閃 1.2 秒, 面板沒有預告會拿到什麼)
- 邊界: 純爽感、不含資訊的演出不需要留存

### P19 資訊盡量貼著它描述的物件
- 狀態: 成立(史萊姆擴張 第 9 輪升格) / 來源: 外部 / 性質: 可讀性 / 跨遊戲: 未驗證
- 理念: 描述某物件的資訊放在該物件旁邊, 讓玩家不必把視線移到別處再對回來
- 犧牲: 盤面上的元素變多(受 P6、P12 約束)
- 證據: 外部: game-ui-design(Diegetic UI); 經驗「指示箭頭與標籤停在被指物件旁的空白處」; 老闆回饋(史萊姆擴張 第 9 輪)說明第 3 頁「『← 目標看這裡』指著任務面板右側的空白區, 視覺上不夠緊密, 第一眼看不懂右上角的排版。改為直接在任務面板上畫圈, 或移到左側變成『目標看這裡 →』指著離字近的地方」。驗收: 卡牌遊戲的教學「這張卡的費用」標籤貼在費用角 vs 放在卡旁空白, 選得出前者; 塔防的射程說明貼在塔上一樣適用
- 邊界: 需要頻繁查看或互相比較的資訊放固定位置; 與 P12 衝突時 P12 優先; **同一份資訊已有固定位置的讀數時, 貼在物件旁的那份只能是最低權重的記號(短線、小箭頭), 不能再做成一份帶字的完整讀數**(史萊姆擴張 第 10 輪: 盤面上的「下次開這側」整欄虛線框 + 字被點名太搶眼, 面板第二欄早已寫了「向左長一欄」)。**「貼著」指長在物件本身(物件的輪廓、光暈、外緣), 不是在物件旁另掛一個帶框的標籤或一排記號**: 事件回饋浮在物件旁的獨立小卡會被讀成「旁邊加東西」(捕泡手 第 9 輪縮邊界: 氣泡上方帶尖角的沾上標籤 + 下方 3 個級數拍點, 老闆「表現應著重在泡泡本身的設計, 不要在旁邊加東西」; 見候選 P22)

### P20 資訊分層, 細節等玩家要時才展開
- 狀態: 候選 / 來源: 外部 / 性質: 可讀性 / 跨遊戲: 未驗證
- 理念: 一眼層只放決策必要的; 次一層在滑鼠停留或選取時出現; 完整細節要玩家主動打開
- 犧牲: 細節不再一眼可見, 需要多一個動作
- 證據: 外部: game-ui-design(Progressive Information Disclosure)
- 邊界: 規則狀態不可藏到第二層以下(P2 優先)

### P21 示意圖要選對錯理解會分岔的例子
- 狀態: 成立(史萊姆擴張 v20 升格: 兩條經驗、兩條不同規則的說明頁) / 性質: 可讀性 / 跨遊戲: 未驗證
- 理念: 用來教規則的圖(說明頁、教學、提示), 要挑「正確規則」與「玩家最可能的錯誤理解」會畫出不同結果的那個例子; 兩種理解畫出同一張圖的例子, 等於沒教到分界
- 犧牲: 示意盤面變複雜, 要多放為了分岔而存在的元素(中途的支撐點、不相連的對照塊、打叉的反例)
- 證據: 經驗「說明頁的例子讓正確規則與錯誤理解畫出同一張圖」(史萊姆擴張 v18 guide 修訂, 重力下落); 經驗「結束條件只畫結束的樣子」(史萊姆擴張 v20 guide 修訂, 結束條件)。驗收: 換成平台跳躍的教學圖, 一樣要挑「差一點沒跳上」與「剛好跳上」並排; 兩個版面(只畫結束畫面 vs 結束畫面 + 一格超出的對照)選得出後者
- 邊界: 規則本身沒有常見的相鄰誤解時不必刻意造分岔; 分岔元素仍要是規則上成立的盤面(P3 的說明頁經驗優先)

### P22 回饋長在物件本身, 不在旁邊另掛圖示
- 狀態: 候選(證據一條) / 性質: 品味 / 跨遊戲: 未驗證
- 理念: 發生在某個物件上的事件回饋, 用物件自己的輪廓、外緣、光暈、內部變化來表現; 不在物件旁另放獨立的小卡、標籤、圖示或一排記號
- 犧牲: 少了「直接寫出結果值」的標籤, 結果要靠物件本體的變化(新顏色、新形狀)與貼著外緣的光環讀; 級數這類計數要編進物件的光暈或輪廓圈數, 不能另列成可數的點
- 證據: 老闆回饋(捕泡手 第 9 輪)「不太喜歡對到拍子時的氣泡表現(氣泡旁類似對話框的 icon 與下方 3 個點點); 表現應著重在泡泡本身的設計, 不要在旁邊加東西」(經驗「回饋的級數與結果值掛在物件旁」)。驗收: 塔防「這座塔升級了」, 塔身外緣亮一圈並多一層輪廓 vs 塔頂浮一個帶框箭頭圖示, 選得出前者; 卡牌連鎖時的增益, 卡框發光加層 vs 卡旁浮一個 +1 徽章同理
- 邊界: 物件在事件當幀就消失(觸發、爆掉)時, 回饋長在它最後的位置, 形狀仍取物件本身(該作: 氣泡大小的一團光往外擴); 與 P9 衝突(滿場時長在物件上的回饋撿不到)時, 先加大光暈與輪廓的尺度與對比, 仍不夠才回報製作人, 不自行加回旁掛標籤; 常駐讀數(HUD、面板)不在此列

## 經驗

### 版面 / 遮擋

- 事件提示(延展、重抽、獎勵、連鎖)蓋住常駐資訊(進度數字、色票、進度條) → 事件層與常駐層共用同一塊版位, 只靠時間錯開 → 常駐資訊有專屬矩形, 事件提示一律排在其外; 真的要疊時只疊在該側的空白區, 不疊在任何數值上〔P1〕。物件層再現(捕泡手 v3 建置自查, 預防性修正、非老闆回饋): v2 把捕捉 / 錯色的勾叉畫在網中央, v3 規格改成網中央常駐目標數字、捕捉當幀就換新數字 — 沿用舊回饋會在玩家最需要讀新數字的 0.5 秒蓋住它 → 規格把某個物件的中央改成決策資訊時, 回頭掃一遍原本畫在該物件中央的所有事件回饋, 移到物件邊緣(該例: 網右上緣的小底圓)
- 事件內雖然依序進場, 老闆仍看成「一堆字同時冒出來, 什麼都沒看到就消失」(史萊姆擴張 第 8 輪: 解鎖卡片 → 清色球卡片 → 新任務橫幅, 規格寫依序 1.5 秒) → 美術讓先進場的卡片保留到事件結束, 後面的一塊一塊疊上去; 每塊只分到 0.3~0.4 秒, 短於讀完一行字的時間; 而且其中一塊(新任務公告)重述了常駐面板馬上會自己顯示的東西 → 一段只放一件事, 前一件退場後下一件才進場, 含字的段至少約 1 秒; 事件層不重述常駐面板會自己換掉的資訊(面板本身的變化就是公告)〔P13〕〔P7〕
- 盤面上的標示(數字、符號)蓋住它所描述的物件本身 → 標示置中在格位上 → 錨在格角並縮到格位的 1/4 以內, 讓被描述的顏色/形狀維持可讀〔P6〕
- 動作處的事件回饋蓋住正在操作的物件(捕泡手 v13 建置截圖自查, 非老闆回饋: 踩拍回饋畫在被拖曳的氣泡上, 初稿是實心填色星芒 + 中心閃光, 截圖上氣泡的顏色被粉色蓋住約 0.3 秒, 玩家正在決定往哪拖) → 「畫在動作發生處」(P19)時只想到位置, 沒想到那個位置當下正是玩家要讀的物件 → 畫在操作中物件上的回饋, 中心挖空到比物件大(該作: 挖空半徑 ≈ 物件拖曳時的外徑), 演出只佔物件外圍一圈; 只有物件在事件當幀就消失時(收下、熄滅的槽位)才可以實心〔P12〕〔P1〕〔P19〕。捕泡手 v16 建置截圖自查再現: 踩拍回饋的輪廓幾何上已在氣泡外緣之外, 但線上的外光(shadowBlur)往內滲, 第 3 級把金黃氣泡染成黃綠 → 挖空要連外光一起挖: 用「大圓減物件外緣」的反向剪裁包住整個回饋, 不只靠幾何半徑。說明頁再現(捕泡手 v15 guide 截圖自查): 「沾錯會消失」那格把碎片回饋畫在染色區中心, 碎片蓋住了造成沾錯的那塊色 B, 圖上看不出是擦到哪一色才消失 → 示意圖裡事件的位置照規則的判定時刻擺(氣泡圓剛碰到地板邊緣那一刻), 讓造成事件的物件留在旁邊看得到
- 指示箭頭與標籤停在被指物件旁的空白處, 老闆第一眼看不懂排版(史萊姆擴張 第 9 輪: 說明頁「← 目標看這裡」擺在任務面板右邊, 箭頭尖端落在面板右側的空白區, 離「目標」兩個字還有半個面板寬) → 為了不蓋住物件, 把指示整組推到物件外、找空的地方放, 箭頭只指到物件的外框方向 → 指示直接落在被指的那一塊上: 用虛線圈住那一塊本身(圈就是指示), 標籤與短箭頭緊貼圈的外緣、從離字最近的一側進來; 箭頭尖端必須碰到圈或字, 不能停在空白〔P19〕〔P6〕

### 視覺層級

- 規則上的關鍵判定線(中線、安全線、分界)被其他元素淹沒 → 所有元素同一個權重 → 判定線的層級最高: 畫在所有盤面內容之後, 給它描邊或外暈保證任何底色上都讀得到, 並且不隨遊戲階段淡出〔P1〕
- 資訊密度逼近上限(同時有數字、符號、輔助線、狀態標示) → 每加一個元素就加一種顏色或一種亮度 → 先排層級再配色: 判定線 > 玩家當下要決策的資訊 > 常駐狀態 > 事後回饋; 同層級才比大小與顏色〔P1〕
- 常駐面板的幾個欄位只用 1px 分隔線隔開, 老闆讀不出「這個面板有 3 塊」(史萊姆擴張 第 9 輪: 任務面板「目標 / 獎勵或解鎖 / 剩餘」要更清楚讓玩家知道有 3 塊) → 分隔線比欄內的圖示與字弱太多, 欄位的邊界在第一眼被內容淹掉; 欄位標籤又是 12px 次要字, 也撐不起分塊 → 要玩家先讀出「有幾塊」的面板, 每塊給自己的底卡(比面板底亮一階、塊與塊之間留空隙), 分塊靠面積而不是靠線; 揭示或清空期間空底卡照畫, 空位本身就在講「這裡有幾格」(v25 修正, 待老闆試玩確認)
- 貼近物件的重述標示畫成了第二份完整讀數, 老闆嫌太搶眼(史萊姆擴張 第 10 輪: 盤面旁「整塊的虛線加上下方的字『下次開這側』, 視覺呈現太強烈」; 同一件事面板第二欄已寫「獎勵: 向左長一欄」) → 為了貼近(P19)在盤面上畫, 卻用整欄虛線框 + 字把它做成和面板同份量的讀數; 那是一局裡遠期、不影響這一塊放哪的資訊, 權重卻和盤面內容同級。美術從 v20 起就在回報裡標出它與「拿掉測試」衝突, 卻保留原樣等老闆點名 → 已有固定讀數的資訊, 貼近標示只留最小的錨點記號(短線 + 小箭頭、半透明、無字), 記號與固定讀數用同一個圖形串起來; 自己標出「拿掉測試不過、規格也沒要求」的元素, 當版就先降到最低權重, 不要只寫進張力清單(v26 修正, 待老闆試玩確認)〔P1〕〔P7〕〔P19〕
- 本體已一眼可讀的資訊再用數字、字樣或符號重述, 老闆讀成「畫面很花、更難識別」(史萊姆擴張 第 5 輪: 團顆數徽章、預覽的「含重力球」字樣、色塊上的形狀符號三條同時被點名) → 加標籤時只問「這資訊重不重要」, 沒問「本體是不是已經說清楚了」 → 加任何標籤前先做拿掉測試: 拿掉它, 玩家看本體(顏色、圖示、盤面本身)還讀得出, 就不加; 規格明文要求的標示照畫, 但在回報裡標出它與本條衝突, 讓製作人決定〔P7〕。第 11 輪再現(史萊姆擴張: 盤面頂線旁的「頂線」小字, 老闆「有點多餘, 可以直接拿掉」): 那行字從早期版本一路沿用, 每版只對新加的元素做拿掉測試, 舊元素沒人重驗; 線本身是橘色虛線、橘色在全畫面只代表結束 / 危險, 字只是在重述線 → 沿用或修正任務時, 拿掉測試也要掃一遍畫面上既有的每個字樣標籤, 不只新增的; 判定線這類本體有專屬顏色與線型的元素, 預設不配名稱字樣, 名稱留給說明頁(v27 修正, 待老闆試玩確認)

- 倒數環以總時長為滿, 和中央數字重述同一件事, 老闆要求改成「一圈 = 這一秒」(捕泡手 第 2 輪: 「讓玩家把重心放在『進度條走完之前趕快凍結這個數字』」) → 套 P17「圖形給趨勢、數字給精確」時, 讓環與數字描述同一個量(總剩餘秒數), 環只是數字的圖形版; 玩家的決策單位卻是「這個數字還能停多久」(數字一跳就錯過窗口), 那一段數字給不出來、環也沒畫 → 設計進度圖形前先問「玩家在等哪一個刻度」, 圖形畫到那個刻度為止、每過一格重跑; 數字已給的總量不再用圖形重述。該作: 環長 = 剩餘 − (顯示數字 − 1), 凍結時換色(v6 修正, 待老闆試玩確認)〔P1〕〔P7〕〔P17〕。(捕泡手 v7 / v8 規格刪除氣泡上的數字, 依 P17 邊界「沒有數字時圖形照舊畫總進度」環改回 12 秒總剩餘比例, 本條在該作無法再驗)
- 數量很多的危險地塊用滿飽和紅框 + 紅紋, 截圖上整片紅壓過網與氣泡(捕泡手 v8 建置截圖自查: 19 塊洗除區排成牆, 第一張截圖最搶眼的是牆, 不是要送的氣泡與要去的網) → 單塊設計時只問「一眼看不看得出危險」, 沒乘上數量; 危險色的面積隨塊數線性放大, 權重跟著放大 → 同一種物件場上會超過約 10 塊時, 用滿場截圖定它的權重: 保留危險色的色相與紋理(辨識靠這兩個), 把框與紋的不透明度降到約 0.3~0.6, 讓它退到網與操作中物件之下〔P1〕〔P9〕(待老闆試玩確認)
- 換皮把背景調亮(捕泡手 v15 第 1 首改成橘 → 玫瑰暖漸層), 原本靠暗背景撐住的亮邊外光與透明氣泡的白邊在亮背景上失效(建置截圖自查, 非老闆回饋: 金黃亮邊的外光在橘底上看不見, 拖出內圈的透明氣泡只剩一圈白) → 骨的可讀性是在暗背景上驗收的, 換皮時沒有重驗 → 會移動到背景上的物件(拖曳中的氣泡)與壓在背景上的關鍵線(亮邊)自帶深色襯底或外描, 不靠背景剛好是暗的; 換皮後用每一關的滿場截圖重驗骨(待老闆試玩確認)〔P10〕〔P9〕。捕泡手 v18 建置再現(設計判斷, 非老闆回饋: 第 1 關改成明亮森林, 比 v15 更亮): 除了物件自帶襯底, 再在背景層、遊戲區周圍鋪一圈由內往外淡出的暗化(該作: 內圈外到網牆外一帶的「林蔭」), 讓關鍵線所在的那一帶永遠是暗底, 亮度留給畫面四角的裝飾; 光門內緣的像素掃描驗收照跑, 確認亮背景沒有讓掃描提前觸發
- 被按住(按下未拖)與拖曳中同樣凍結倒數, 若只有拖曳有外觀, 按住不動時玩家看不出「已經凍住了」(捕泡手 v6 建置設計判斷, 非回饋) → 規格新增狀態時只沿用舊狀態的外觀差(放大 + 影子), 那個差描述的是「被拿起來」而不是「凍結」 → 規則上共享的效果(凍結)用一個共同記號(秒環變冰藍), 狀態之間的差(拿起來與否)另用放大 / 影子表達; 顏色只給凍結一種意義(待老闆試玩確認)〔P2〕〔P3〕〔P16〕

### 語意一致

- 同一個概念在不同地方用不同顏色或形狀 → 各區塊各自設計 → 建立全局語意色(例如左/右、敵/我、安全/危險), 盤面、側欄、結算標籤、提示全部共用同一套〔P3〕
- 同一個物件上要同時標兩個計數(捕泡手 v3 建置設計判斷: 氣泡倒數秒數 + 剩餘可續次數, 旁邊的網也掛數字), 若都用數字, 玩家要先分辨「哪個數字是哪種」才能比對, 次數最可能被誤讀成另一個秒數 → 沿用上一版「角落小圈寫數字」的做法時, 沒注意 v2 那個數字本來就是秒, 語意相同; v3 改成次數後語意變了、長相沒變 → 畫面上的數字只保留給一種量(本例: 秒 / 目標秒), 其他計數改用可數圓點(實心 = 剩、暗 = 用掉); 規格把某欄位的意義換掉時, 即使欄位位置沒變也要換長相(待老闆試玩確認)〔P3〕。(捕泡手 v6 規格改為續命不限次數、氣泡上不顯示次數, 圓點刪除, 本條無法在該作再驗)
- 條件標示把「不比對」的屬性也畫出來, 玩家會讀成「要這個值」(捕泡手 v8 建置設計判斷: 網條件「只要色 A」若在網中央放一個色 A 實心圓當標籤, 形狀條件出場後, 圓會被讀成「要圓形」; 規格明定網沒列的屬性不比對) → 為了讓「顏色條件」有個看得見的標籤, 挑了一個帶預設形狀的符號, 符號的形狀本身在同一本字典裡另有意義 → 條件標示只畫有列的項目; 能由物件本身承載的條件(網的色框 = 顏色)就不另加符號, 形狀條件出場時才在中央加形狀符號; 符號與遊戲內物件共用同一套形狀路徑(待老闆試玩確認)〔P3〕〔P7〕
- 規格要求每關換整套風格, 但同一套辨識規則每關都要成立(捕泡手 v14 建置設計判斷, 非老闆回饋: 三首歌三關, 網牆、氣泡、場地、背景、HUD 全換) → 若把「換整套」理解成每關各自重設計, 物件類別的分法(立體 vs 平塗、空心 vs 實心、粗亮 vs 細暗)會跟著被換掉, 玩家每關要重學一次 → 先把畫法拆成「骨」與「皮」兩層: 骨 = 類別與屬性的區分手法(三關不變), 皮 = 背景、地面紋理、線型、色組、拍子提示造型(每關換); 同一組函式以關卡序號取皮, 骨寫死在函式裡。跨關殘留的物件(換關當下拖曳中的那一顆)與它要比對的目標(舊網)一律用同一關的色組, 用一個 `paletteLevel` 欄位傳(待老闆試玩確認)〔P3〕〔P0〕。第 8 輪老闆回饋(捕泡手): 「每一關雖然風格和歌曲變了, 但感覺沒有太大的差異性, 差異要做得更突出」 → 「骨」守住了, 但「皮」換得太保守: 三關背景都是暗色漸層、都靜止、網牆都是同一條線只換線型, 縮圖上三關幾乎同一張圖; 差異都落在近看才看得到的細節(線型、地面紋理) → 皮的差異挑縮圖尺度就看得出的軸, 而且一次拉到極端: 色溫(暖 / 冷 / 無彩)、背景明暗、質感(珠串 / 發光管 / 鋼塊)、背景動態(漂浮 / 隨拍脈動 / 跟關卡特色週期同步的掃描); 背景動態綁到該關的音樂或特色週期, 讓動態本身也在講話(P8), 並壓在低不透明度、只放在遊戲區外(P1)。背景改亮時連帶檢查骨的可讀性(見經驗「換皮把背景調亮」)。答不出違反哪條理念: 這是「玩家感受得到的變化」而非可讀性, 不掛理念(v15 修正, 待老闆試玩確認)
- 兩種語意不同的事件看起來一樣, 玩家分不出「我造成的」與「系統給的」 → 只有顏色不同 → 形狀語言也要不同(方角 vs 圓角 vs 六角、外擴 vs 內收、箭頭方向相反)〔P4〕
- 主題指定的裝飾要用到字典裡的保留色(捕泡手 v18 建置設計判斷, 非老闆回饋: 老闆要第 2 關舞廳「點綴紅色花朵」, 紅在本作只代表危險與扣血, 規格又要求危險紅三關一致) → 照字面畫紅花, 背景裝飾就和危險共用一個長相; 若改去動危險紅, 又違反「一個意義一種長相」的跨關一致 → 保留色不動, 從裝飾那一側讓開, 而且一次讓多條: 色相移到不同色名(紅 → 粉洋紅, 配亮粉與酒紅陰影讀成「粉玫瑰」)、位置鎖在離保留色出現處最遠的角落、動態反過來(保留色在脈動 → 裝飾完全靜止不發光)、形狀語言換成背景專用的(像素拼花 + 綠莖葉); 在 style.md 把四條逐條寫出來讓製作人驗收。大型主題角色(魔龍)同理: 只做低對比剪影, 用判定區同一套幾何(該作: 離圓心的八邊形距離)算出「裝飾最近只能到哪」, 寫成程式裡的篩選條件而不是目測擺位; 眼睛之類的亮點也避開保留色與拍子專屬色(待老闆試玩確認)〔P3〕〔P0〕〔P12〕

### 狀態可辨識

- 「什麼都沒發生」與「機制壞掉」分不出來 → 零效果的事件無聲跳過 → 零效果也要有可單獨辨識的回饋, 且與有效果的版本形狀不同〔P2〕。捕泡手 v10 建置再現(設計判斷, 非回饋): 規格改成每種屬性只沾一次, 已沾色的氣泡再擦過區域屬性不變; 若無聲跳過, 玩家分不出「沒擦到」與「擦到但鎖住了」 → 生效用實線環往外擴、已鎖定用灰虛線環往內收, 線型與方向都相反(待老闆試玩確認)
- 一組格位「屬於同一個整體」讀不出來, 玩家誤以為是各自獨立 → 只標個別格位 → 用連接桿、共同輪廓、共用紋理或編號徽章表達歸屬; 只要規則上會「整組一起動」, 歸屬就必須畫出來〔P2〕
- 系統一次移除一大片格位, 玩家讀不出那是哪條規則、以為「消了太多」(史萊姆擴張 第 5 輪: 「為什麼開地之後會消除這麼多方塊? 我以為只有削頂而已」) → 只逐格標記被移除的格, 沒畫出規則的整體形狀, 而且緊接在觸發它的消除之後 → 用一條連貫的圖形畫出規則本身的形狀(該例: 沿盤面輪廓的一條削線 = 「削掉最上面一層皮」), 並在事件內與前一段消除分時演出, 不從事件第一幀起跑〔P2〕(v15 修正, 待老闆試玩確認)
- 常駐面板的欄位標籤寫成問句(「做什麼 / 得到什麼 / 還差多少」), 老闆要求改短(史萊姆擴張 第 8 輪: 「目標 / 獎勵 / 剩餘」, 拿到的是新要素時寫「解鎖」而不是「獎勵」, 「用字越少越好」) → 為了讓新手第一眼讀懂, 把欄位的用途寫成完整一句; 常駐欄位看久了標籤只剩「找欄位」的功能, 長標籤反而搶內容的注意力 → 常駐欄位標籤用最短的名詞(兩個字), 退成 textDim 小字; 標籤可以跟著內容性質換字(獎勵 / 解鎖), 但位置與樣式不變〔P7〕
- 介面標籤直接用規格內部名稱, 玩家看不懂(史萊姆擴張 第 5 輪: 「開地之後的任務是『延伸』, 是延伸什麼? 看不太懂」) → 照抄規格的關卡名 / 階段名上畫面 → 標籤一律寫玩家語言的「做什麼 / 得到什麼」, 規格名詞(階、關卡名、機制代號)不上畫面〔P0〕
- 冷卻中的物件畫了剩餘進度的扇形, 截圖上卻幾乎看不到扇形(捕泡手 v2 建置時截圖自查: 網冷卻 0.4 秒與 1.3 秒看起來一樣, 只剩中央數字能讀) → 「暫時不可用」先把整個物件調暗, 再疊一塊更暗的「剩餘」扇形, 暗疊暗兩半沒有對比, 圖形那一半資訊等於消失 → 冷卻 / 進度圖形的兩半至少一半要比停用底亮: 已恢復的那塊用物件本色(約 40% 不透明)、剩餘的那塊用深色, 停用感改由外框(虛線)與網格變暗承擔; 畫完用最短與最長剩餘各截一張圖比對〔P16〕〔P17〕。(捕泡手 v3 規格刪除網冷卻, 本條無法在該作再驗, 等別的遊戲出現冷卻 / 進度物件)
- 「還沒取得屬性」的物件若畫成一種淡色, 會被讀成多一種顏色(捕泡手 v8 建置設計判斷: 氣泡生成時透明, 要擦過染色區才有色) → 把「無」當成色票裡的一個值來配色(淺灰、淡白), 它和四色只差明度, 跟「第五色」長得一樣 → 「無屬性」與「有屬性」換一條通道: 有色 = 實心填色, 無色 = 空心框 + 極淡填色; 同一套「無色 = 空心灰白」也用在其他不帶顏色的物件(該例: 賦形區), 讓「灰白 = 無色」成為一個字典詞(待老闆試玩確認)〔P3〕〔P4〕
- 可拿起的物件與地上的地塊同為平面圓、尺寸相近、共用色票, 老闆讀成「三者長太像, 辨識度很差」(捕泡手 第 5 輪: 染色區、賦形區、氣泡; 老闆建議只改氣泡, 「讓氣泡看起來更有可互動感」) → 每種物件各自設計時只在細節上分(氣泡多一小塊高光與外圈細環、地塊多一個中央符號), 外形、尺寸(半徑 20 vs 24)、平塗手法都一樣; 加上上一條把「無色 = 空心灰白框」同時套在透明氣泡與賦形區, 字典詞共用反而把兩種物件拉成同一個長相 → 先分「能操作的」與「場景的」兩大類, 兩類用不同的繪製手法區分(該作: 氣泡 = 立體漸層 + 主高光 + 反光弧 + 常駐落影, 地塊 = 平塗無影), 而不是在同一手法裡加細節; 共用字典詞(顏色、灰白 = 無色)時, 只共用「屬性」那一層, 物件類別那一層要先分開; 可操作物件再加滑鼠停留的浮起(外部準則「可互動的元素在滑鼠停留時要有外觀變化」)。驗收用「物件壓在同色地塊上」的截圖(v12 修正, 待老闆試玩確認)〔P0〕〔P4〕〔P3〕
- 規格建議預告用半透明, 但半透明在遊戲內已有別的意義(捕泡手 v8 建置設計判斷: 規格寫「預告中的區域與網半透明或類似」, 而彈回中的氣泡從 v2 起就是半透明 = 不可按) → 照規格的建議字面做, 同一個長相就同時代表「彈回中」與「即將生效」 → 規格對呈現只給建議時, 先查這個長相在字典裡是否已被佔用; 過渡狀態用「虛線外框 + 由中心長大的填色, 填滿那一刻 = 生效」, 同時表達「還沒生效」與「還有多久」; 出場提示改用與所有圓環不同形的角框(待老闆試玩確認)〔P3〕〔P16〕。捕泡手 v12 建置再現(設計判斷, 非回饋): 波次的「氣泡冒出」與「清場」都需要新回饋, 最順手的「外擴白環」已代表「屬性變了 / 被收下」 → 冒出改用地面扁橢圓水紋 + 本體從地面彈起(過渡狀態用 `spawnT` 畫在同一個物件函式裡, 冒出中照常可按), 清場改用填滿內圈地面的亮光(面, 不是線)

- 物件換位時只在新位置畫出場提示, 玩家視線還停在舊位置(捕泡手 v10 建置設計判斷, 非回饋: 同時只亮一張網, 收下一顆就換到至少 90° 外的槽位, 規格待定擔心「找網」) → 沿用「新出場 = 角框」只貼在新物件上, 要靠周邊視覺撿到; 視線正停在剛放下的舊位置, 新位置離得越遠越難撿 → 換位類事件從舊位置出發畫一道連到新位置的動態(該例: 沿槽位軌道的掃光, 約 0.5 秒), 讓視線被帶過去, 新位置再加字典裡的角框; 舊位置的結果回饋(勾)與掃光起點在同一處先後出現, 不另開視線落點。這種動態每次事件都播, 在 style.md 標出它是全場唯一的大動態, 試玩嫌吵時可只拿掉連線(待老闆試玩確認)〔P1〕〔P8〕〔P19〕
- 事件回饋只畫在物件的某一個狀態下, 規格讓物件在事件當幀就換狀態, 回饋跟著畫不出來(捕泡手 v10 建置自查: v8 的捕捉勾寫在網「啟用中」的分支裡; v10 捕捉當幀原槽位就熄滅, 照搬的話勾永遠不會出現) → 回饋掛在狀態分支裡, 沿用時沒重對「事件之後物件處於哪個狀態」 → 規格改了狀態轉換的時機時, 逐一檢查每個事件回饋是在事件前還是事件後的狀態上播; 會跨狀態的回饋畫在狀態分支之外, 並在 style.md 的狀態對照寫明要傳給哪個狀態〔P2〕〔P16〕
- 時機類提示只在時刻到了才變, 玩家無法預判下一次(捕泡手 v13 建置設計判斷, 非老闆回饋: 規格要求拍子「能從畫面預判下一拍何時到, 不只是拍到了才有變化」) → 最順手的做法是到拍時閃一下或脈動一下, 那只在事後告訴玩家「剛剛是拍」; 而外擴線環在字典裡已代表「屬性變了 / 被收下」 → 加一個連續、單向收攏到判定位置的元素(該作: 拍子粉細環從內圈外 24 像素往內收, 收到邊線那一刻 = 下一拍; 到拍時邊線再閃), 玩家看「還差多遠」就能預判; 收攏方向刻意與字典裡的外擴環相反, 並給拍子一個專屬色; 這種常駐動態要壓到最低權重(細線、半透明、不進到遊戲物件所在的地面), 在 style.md 標出它是全場唯一常駐動態(待老闆試玩確認)〔P16〕〔P3〕〔P8〕
- 連續量的小幅增減在條上只有幾像素, 亮段又與條本體同色系, 「加了一段」看不出來(捕泡手 v13 建置截圖自查: 命 0~100 畫在 182 像素的條上, 踩拍回 2 點只有約 4 像素; 條本體初稿是近白, 捕捉回命的亮段也是白) → 單獨設計條本體時挑了最好讀的亮色, 沒想到回饋要疊在它上面; 也沒把「最小一次變化」換算成像素 → 設計進度條時先算最小一次增減是幾像素, 不到約 6 像素就讓回饋亮段畫到最小寬度並加外框外光(回饋可以誇大, 讀數不誇大); 條本體用中明度, 把最亮的白與專屬色留給「剛變化的那一段」。與經驗「冷卻扇形暗疊暗」同一根因: 疊在一起的兩層沒有對比(待老闆試玩確認)〔P16〕〔P4〕
- 貼在物件上的回饋只用物件尺寸級的細環, 老闆說「沒有任何回饋」「氣泡一大堆時很難看清楚自己有沒有沾對」(捕泡手 第 7 輪, 沾地板回饋; v10 起是生效外擴實線環 / 已鎖定內收灰虛線環, 環半徑只比氣泡大幾像素) → 設計時以單顆氣泡的特寫判斷, 環與壽命環、懸停框、其他氣泡的輪廓同尺度同形狀, 滿場時被當成背景雜訊; 而且環只說「有事發生」, 沒說「沾上了什麼」, 玩家還要回頭看氣泡本體顏色才知道對不對 → 物件上的結果回饋要離開物件的輪廓帶: 浮在物件外(該作: 氣泡正上方的標籤, 帶指向尖角)、直接寫出結果的值(色塊 = 沾上的色、白形狀 = 沾上的形, 鎖定用灰底鎖頭)、白框 + 深色外描保證壓在任何東西上都讀得到; 環只當輔助。驗收以滿場(約 10 顆 + 多個回饋同時)的截圖為準, 不用單顆特寫(v14 修正, 待老闆試玩確認; 本輪無法確認 RD 上一版是否有接上回饋, 若是沒接上, 本條仍成立: 環的尺度本身就撐不住滿場)〔P9〕〔P19〕〔P2〕。**第 9 輪老闆否決了這條的解法**(浮在氣泡上方帶尖角的標籤被讀成「類似對話框的 icon」, 見下一條經驗與候選 P22): v16 改成不用標籤, 只留「離開輪廓帶」那一半 — 光環加粗加大(從外緣擴到約 3 倍半徑、帶外光與深色外描), 用沾上的那個色; 「沾上了什麼」交給氣泡本體已換的顏色。本條「環要撐得住滿場」的判斷仍成立, 「用浮動標籤寫出結果值」不再適用
- 踩拍特效只有一種強度、造型與音樂無關, 老闆「不喜歡, 換一種表現方式」並要求第 1 → 2 → 3 次漸強(捕泡手 第 7 輪; v13 是粉色星芒 + 菱形) → 星芒是通用的「閃一下」, 和「對上拍子」這件事沒有語意連結, 也沒有分級空間 → 有分級的回饋先選一個「可以數」的元素當骨架(該作: 氣泡兩側的音波弧, 組數 = 級數; 下方 3 個拍點亮幾個 = 第幾級), 強度再疊粗細、長度與外光; 造型取自事件本身的語意(拍子 → 聲波), 色用該關的拍子專屬色。老闆的「不喜歡」本身屬品味, 沒給原因, 不據此立理念(v14 修正, 待老闆試玩確認)〔P15〕〔P4〕。第 9 輪老闆再次否決(下方 3 個拍點, 見下一條), 「可數的元素」改編進物件本身的輪廓圈數
- 回饋的級數與結果值掛在物件旁, 老闆讀成「旁邊加東西、像對話框」(捕泡手 第 9 輪: 「不太喜歡對到拍子時的氣泡表現(氣泡旁類似對話框的 icon 與下方 3 個點點); 表現應著重在泡泡本身的設計, 不要在旁邊加東西」。對話框 = 沾上回饋那個浮在氣泡上方、帶指向尖角的標籤, 踩拍常與沾上同一刻發生, 老闆把兩者看成同一個踩拍表現) → v14 為了「滿場撿得到」(P9)與「級數可數」(P15), 把結果值做成浮動標籤、把級數做成氣泡下方一排拍點; 兩者都是物件以外的獨立小件, 而且拍點重述了音波弧組數、標籤重述了氣泡剛換上的顏色 → 回饋長在物件本身: 級數編進貼著外緣的輪廓圈數(1 / 2 / 3 圈, 越高越粗越亮、第 3 級最內圈換白), 外加物件外緣一圈光暈; 結果值交給物件本體的變化 + 用結果色畫的外擴光環; 兩種同時發生的回饋靠顏色(屬性色 / 拍子色)與動態(外擴 / 原地震動)分開(v16 修正, 待老闆試玩確認)〔P7〕〔P19〕〔P22 候選〕
- 規格要求「場上每顆都隨拍變化, 但外緣不准動」, 第一版變化在縮圖上幾乎看不出(捕泡手 v16 建置截圖自查, 非老闆回饋; 老闆第 9 輪要求「場上所有氣泡要跟著節奏輕微跳動」, 規格把位移與縮放都禁掉, 理由是畫面接觸要等於判定接觸) → 只在本體內緣加一圈亮邊(最寬 3.5 像素、不動), 尺度小又沒有位移, 和靜止幾乎一樣; 而本作第二辨識通道是明度, 整顆變亮變暗又被禁止 → 「跳」改由本體內部的位移元素承擔: 高光往上跳 5 像素再落回(像內容物被震了一下)+ 一道細波紋從本體邊收向中心(像鼓皮被敲), 外加內緣短暫加粗; 都在每拍開頭 40% 內做完, 用本體自己的邊色, 不出現拍子色(拍子色留給「這顆對上拍子」的回饋, 一眼分得出常態與事件)(待老闆試玩確認)〔P15〕〔P8〕〔P4〕
- 畫面上的接觸早於判定, 玩家看到氣泡已貼上光門卻沒觸發, 回報成 bug(捕泡手 第 9 輪「有時候拉著氣泡去碰網, 沒有觸發」, RD 查出 12 例畫面已貼上、判定圓還差 1~18 像素) → 美術畫亮邊時以「邊的中線」為準往兩側描粗(線寬 18 + 黑襯底 8 + 外光), 拖曳中的氣泡又放大 1.12 倍、壽命環畫在氣泡外 6.5 像素; 每一層都讓「畫出來的邊」往判定線前面多長幾像素, 加起來到 18 → 會被「碰到」的東西, 畫面邊界一律等於判定邊界: 亮邊從判定帶內緣往外畫(內緣放一條白芯, 外光用剪裁只往外放), 可拖曳物件任何狀態不縮放, 物件外圈的環畫在判定圓上而不是判定圓外; 驗收用 headless 截圖沿法線掃像素, 找第一個亮像素的位置與判定邊界比(該作 24 個光門全部在 ±1 像素內)(v16 修正, 待老闆試玩確認)〔P2〕
- 同一顆物件上同時出現兩種回饋(沾上光環 + 踩拍音波弧), 初稿兩者半徑相同, 截圖上踩拍弧被光環吃掉(捕泡手 v14 建置截圖自查, 非老闆回饋; 規格要求兩者同一刻出現時分得開) → 各自設計時都挑「緊貼物件外圈」這個最自然的位置 → 物件周圍先分方位與半徑帶再分配: 該作上方 = 沾上標籤、外圈 30~40 = 沾上光環、47 起 = 踩拍弧(只在左右)、下方 = 級數拍點; 新增回饋時先查這張分配表〔P4〕〔P13〕。捕泡手 v16 建置設計判斷再現(非老闆回饋, 場地尺度): 規格把血量環放到內圈外緣, 那裡原本是拍子提示收攏的終點與到拍閃光, 危險紅光也要在內圈邊緣 — 三個常駐 / 半常駐元素擠在同一圈, 拍子閃一下就會讓血量環看起來變長 → 同樣先分半徑帶: 內圈內側 = 危險紅光、外緣 = 血量環、再往外 = 拍子提示(收到血量環外側為止、閃光也在外側), 三者顏色與節奏也不同(紅 / 血量色 / 拍子色; 1.3 秒固定週期 / 不動 / 跟拍); 尺寸表寫明每一帶的半徑範圍(待老闆試玩確認)
- 規格在既有回饋分級的兩級之間插一種新回饋, 並明訂「不得像上面那一級」(捕泡手 v17 建置設計判斷, 非老闆回饋, 不算升格證據: 沾上(光門沒要)要比沾上(光門要的)弱、比每拍常態變化強, 且不得出現踩拍 / 整串的任何表現元素) → 最順手的做法是把相鄰一級縮小變淡(同一圈外擴光環改細、改短), 那樣兩者只差強度一條通道, 玩家會讀成「弱一點的同一種事」, 而且外擴、發光、圓環這些元素多半也被上一級用著 → 動手前先把相鄰各級(含要避開的那一級)用到的表現元素逐項列成清單寫進 style.md, 新回饋在「外形」與「動態」各挑一個清單上沒人用的值(該作: 全場回饋裡唯一非圓的輪廓、唯一完全靜止的回饋), 強度高低只當第三條通道; 對比改用暗色平塗墊, 不用描邊或外光(兩者都在清單上); 時長只綁事件經過時間, 不讀拍子相位。驗收截圖讓新回饋與要避開的那一級同框、且畫在拍點上(待製作人驗收)〔P15〕〔P4〕〔P3〕
- 獎勵只在事件裡閃一下, 玩家事後不知道拿到了什麼(同上一條「解完之後也不知道延伸了什麼」) → 獎勵資訊只存在於 1 秒多的事件演出, 常駐面板沒有預告也沒有留存 → 常駐面板預告「做到會得到什麼」, 獎勵結果留在常駐欄(倍率欄、之後出現的新方塊、結算畫面)〔P18〕〔P2〕

### 無障礙

- 只靠色相區分的物件, 色弱玩家分不出 → 三色以上只用顏色編碼 → 每個顏色配一個幾何符號(圓/方/三角/菱), 色票、預覽、落點預示、盤面格全部共用同一套符號〔P4〕〔P3〕。**邊界(老闆回饋, 史萊姆擴張 第 5 輪)**: 老闆明言 prototype 不考慮色覺異常時不加符號(「這個只是 prototype 而已, 不需要考慮色盲的情況, 只需留顏色就好」); 改為把各色明度拉開, 轉灰階仍分得開。進正式版或老闆改口要考慮色弱時, 本條恢復適用
- 同一關的屬性色為了配合主題色溫挑了鄰近色相, 老闆「紅 & 橘、黃 & 橘太相近, 很常沾錯」(捕泡手 第 8 輪; v14 三關最近一對色相只差 46° / 46° / 27°, 灰階卻都拉開了 40 以上) → 先定主題氛圍(暖色關用暖色)再在色盤裡挑 4 色, 驗收只跑灰階; 明度差在靜態並排時看得出, 拖曳中一瞥、單顆對照網條件時, 玩家先讀的是色相名稱(「橘的」), 鄰近色相就叫同一個名字 → 屬性色先排色相再排明度: 4 色色相兩兩 ≥ 約 60°、不得有任何一對落在相鄰色相(紅 / 橘 / 黃、青 / 藍、紫 / 洋紅各自算相鄰), 再把 4 色排成 4 個明度階(相鄰階灰階差 ≥ 35); 用 node 算色相與灰階寫進 style.md。主題色溫交給背景、地面、網牆、HUD 表現, 屬性色不承擔氛圍; 危險紅保留給扣命, 屬性色避開紅區。拍子這類專屬色只用在線與點、不用在實心面, 離 4 色色相再留 ≥ 30°(v15 修正, 待老闆試玩確認)〔P4〕〔P0〕。捕泡手 v18 建置截圖自查再現(換主題重配色, 非老闆回饋, 不算升格證據): 拍子色照「離 4 色 ≥ 30°」挑了螢光黃綠(離翡翠綠 47°), 滿場截圖上同一顆翡翠綠氣泡同時有沾上光環(屬性色)與踩拍光暈(拍子色), 兩者被讀成同一團綠 — 30° 只防「專屬色被讀成第五色」, 沒防「專屬色與屬性色疊在同一個物件上要分開」 → 會與屬性色同框長在同一個物件上的專屬色, 要過與屬性色同一條門檻(不落在同一個色名; 做不到時至少用明度再拉一條: 淡色專屬色 vs 飽和屬性色); 只出現在別處的專屬色(血量環)才可用 30° 的寬鬆門檻。配色後用「同一顆物件同時掛兩種回饋」的截圖驗, 不只看色票表〔P4〕〔P9〕

### 與規格的分界

- 規格說「不做預測性提示」, 美術卻畫出了預測 → 把「現況讀數」與「落點試算」混為一談 → 判準: 輸入只有已鎖定/已確定的狀態才是現況讀數, 任何把玩家當前操作中的物件算進去的都是預測, 不畫〔P5〕

- 說明頁的例子讓正確規則與玩家最可能的錯誤理解畫出同一張圖, 玩家學到錯的版本(史萊姆擴張 v18 guide 修訂: v15 第 4 頁相連的塊落下後剛好停在最底一層史萊姆上, 看起來和「掉到最底」一模一樣, v18 改要求「沒有落到盤底, 讓玩家看出掉到碰到東西為止」) → 只驗算了圖在規則上成立, 沒問「換成錯的規則, 這張圖會不會長得一樣」 → 畫示意圖前先列出這條規則最近的錯誤理解(落到底 vs 落到碰到東西、斜碰算不算、不相連的懸空塊動不動), 挑一個兩者結果不同的盤面(該例: 塊的一側在半空就碰到一根柱子而停下, 下方留著看得見的空洞); 找不到就加一個對照(打叉的反例、原地不動的對照塊)〔P21〕

### 外部準則(game-ui-design 摘錄, 經老闆篩選)

- 操作存在但玩家不知道 → 按鍵只寫在說明文件或不寫 → 可用的操作與對應按鍵顯示在畫面上; 可互動的元素在滑鼠停留時要有外觀變化〔P2〕
- 同一個按鍵或按鈕位置在不同畫面意義不同, 玩家誤按 → 各畫面各自設計 → 確認、取消、返回的位置與按鍵全遊戲固定〔P3〕
- 聚焦或選取狀態色弱看不出來 → 只靠變色表示 → 加外框、外暈或放大, 且在任何底色上都看得到〔P4〕〔P10〕
- 等級、強度、稀有度只能靠顏色認 → 用色相編碼等級 → 用可數的疊加元素表示(無框 / 單框 / 雙框 / 加角飾)〔P4〕
- 文字在某些底色上讀不到 → 對比不足或字重太細 → 對比度至少 4.5:1, 字越小對比要越高; 不用細字重〔P10〕
- 字太小一眼讀不出 → 以設計當下的螢幕判斷 → 字級下限換算成畫布高的比例: 最小約 1/77, 關鍵數字約 1/45(原文 1080p 下 14px / 24px)〔P0〕〔P9〕
- 色弱玩家分不出兩種顏色 → 兩色色相不同但明度相近 → 轉灰階測試, 各色仍要分得開; 紅綠是最常撞的一組〔P4〕
- 關鍵提示出現太慢或消失太突然 → 進退場用同一種節奏 → 關鍵資訊出現即時, 消失要緩(淡出約 500ms)〔P13〕〔P18〕
- 誰疊在誰上面每次臨場決定, 改版後層級錯亂 → 沒有明文的繪製順序 → style.md 列一張繪製層級表; 間距用固定級距(如 8/16/24/32)〔P1〕〔P3〕
- 不可逆的操作被誤觸 → 與一般操作同樣的手續與外觀 → 多一道手續(長按或確認), 外觀與相鄰按鈕不同; 長按要畫出進度〔P2〕
