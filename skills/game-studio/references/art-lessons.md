# 美術經驗

只有美術 agent 讀寫。每條三行內: `- (症狀) → (原因) → (解法)`。跨遊戲通用, 不寫單一遊戲的版位、色票或尺寸 — 那些屬該遊戲的 style.md。同類問題合併, 不重複。

**為什麼需要這份**: 美術每次上工都是全新 session, 輸入只有 spec.md, 前幾版的版面判斷與踩過的坑一概不傳承。同一個遊戲改版重做四次, 就有四次機會重犯同一個錯。

## 版面 / 遮擋

- 事件提示(延展、重抽、獎勵、連鎖)蓋住常駐資訊(進度數字、色票、進度條) → 事件層與常駐層共用同一塊版位, 只靠時間錯開 → 常駐資訊有專屬矩形, 事件提示一律排在其外; 真的要疊時只疊在該側的空白區, 不疊在任何數值上
- 盤面上的標示(數字、符號)蓋住它所描述的物件本身 → 標示置中在格位上 → 錨在格角並縮到格位的 1/4 以內, 讓被描述的顏色/形狀維持可讀

## 視覺層級

- 規則上的關鍵判定線(中線、安全線、分界)被其他元素淹沒 → 所有元素同一個權重 → 判定線的層級最高: 畫在所有盤面內容之後, 給它描邊或外暈保證任何底色上都讀得到, 並且不隨遊戲階段淡出
- 資訊密度逼近上限(同時有數字、符號、輔助線、狀態標示) → 每加一個元素就加一種顏色或一種亮度 → 先排層級再配色: 判定線 > 玩家當下要決策的資訊 > 常駐狀態 > 事後回饋; 同層級才比大小與顏色

## 語意一致

- 同一個概念在不同地方用不同顏色或形狀 → 各區塊各自設計 → 建立全局語意色(例如左/右、敵/我、安全/危險), 盤面、側欄、結算標籤、提示全部共用同一套
- 兩種語意不同的事件看起來一樣, 玩家分不出「我造成的」與「系統給的」 → 只有顏色不同 → 形狀語言也要不同(方角 vs 圓角 vs 六角、外擴 vs 內收、箭頭方向相反)

## 狀態可辨識

- 「什麼都沒發生」與「機制壞掉」分不出來 → 零效果的事件無聲跳過 → 零效果也要有可單獨辨識的回饋, 且與有效果的版本形狀不同
- 一組格位「屬於同一個整體」讀不出來, 玩家誤以為是各自獨立 → 只標個別格位 → 用連接桿、共同輪廓、共用紋理或編號徽章表達歸屬; 只要規則上會「整組一起動」, 歸屬就必須畫出來

## 無障礙

- 只靠色相區分的物件, 色弱玩家分不出 → 三色以上只用顏色編碼 → 每個顏色配一個幾何符號(圓/方/三角/菱), 色票、預覽、落點預示、盤面格全部共用同一套符號

## 與規格的分界

- 規格說「不做預測性提示」, 美術卻畫出了預測 → 把「現況讀數」與「落點試算」混為一談 → 判準: 輸入只有已鎖定/已確定的狀態才是現況讀數, 任何把玩家當前操作中的物件算進去的都是預測, 不畫
