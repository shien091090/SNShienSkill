# 跟使用者講話的用詞

**講話一律用人看得懂的名稱, 不用內部編號或代號當敘述主體。** 流程圖節點編號(`#40`)、ticket 編號、內部代碼、行號, 這些是給機器對照用的。要提的話寫成「步驟名(#編號)」, 名字在前、編號在括號裡當註記, 絕不能只丟編號。

同理適用於程式識別字: 描述行為時轉成中文, 不要丟 function / class 名要使用者自己去查。例外是團隊已慣用的固定稱呼。

**Why:** 2026-09-17 規劃 808MYS 的 LangGraph 流水線時, 我整段用 `#7`、`#18`、`#26` 講設計決策, 使用者直接回「你都用編號我完全看不懂在講什麼」。那些編號是 draw.io 檔案裡的 id, 只有我剛讀過檔案才知道對應哪一步。文件裡留編號可以(機器要對照), 但對話裡用編號等於要求對方背一份對照表。
